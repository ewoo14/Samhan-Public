수식 빌더 에픽 (2026-06-17 개발책임자 방향). 슬3-1(변동DC) 머지(#498) 후 다음 **대단위** 에픽.

**목표**: 종합견적서(estimate-app) + 주문서의 모든 가격/수식 계산을 **백엔드 하드코딩 → 프론트(메뉴) 사용자 직접 설정 기반**으로 전환. 신규 품목 유입 시 코드 변경 없이 메뉴에서 견적서와 같은 수식을 정의.

**개발책임자 방향 (2026-06-17)**:
- 변동DC(boolean 토글, 전역할인율 영향없이 기초납품가 그대로 표시) 옆 **고정DC도 %단위로 설정** (각 품목 고정 DC율). **기초값 = 시트값**.
- 종합견적서 + 주문서의 **모든 수식** 사용자 설정 가능하도록.
- 번들 자동구성 수식(실내기 1대당 맞춤 판넬/리모컨/유연호스 자동포함)도 설정화 — 백엔드 변경이 아니라 메뉴 설정으로.

**슬3-1(변동DC) 박제**: 변동DC 의미 = 전역할인율(거래처 DC) 영향 안 받고 기초납품가 그대로 표시하는 품목 표식. 시트 무관(DB 전환). 단순 boolean 체크박스 토글(별도 컬럼). variableDiscountManual(V19)는 BE 내부 sync 보존용(이 에픽에서 재설계/폐기 검토). **변동DC 계산 적용(전역할인 제외→기초납품가)은 이 에픽 소관**.

**연관**: [[project_quotation_estimate_app_state]](estimate-app ~95% 구현, BundleExpander·PriceCalculationService·dc-config·QuoteSnapshot), [[project_sheets_to_db_full_migration]](외부 시트→DB), [[project_product_master_registration]].

**🚨 GAS parity 필수 (개발책임자 2026-06-17)**: 설정화로 변경하더라도 **GAS(legacy 종합견적서) 동일 기능/계산 유지**가 최우선 제약. estimate-app은 이미 GAS 1:1 이식([[project_quotation_estimate_app_state]]) → **설정 기본값 = 현 estimate-app(=GAS) 수식·시트값**으로 두고, 사용자가 명시 변경할 때만 GAS와 달라지게 설계. GAS 계산 vs 우리 계산 **parity 회귀 테스트 필수**. GAS 원본 = `tools/legacy-gas/`([[project_sp_08_legacy_gas_parity]]).

**관계수식·parity 검증 아이디어(개발책임자 요청 2026-06-17, PM 제안)**: ①**계산식 구조=코드 불변, 값·룰만 설정**(구조 차이 0=parity 자동) ②**설정 기본값=하드코딩·시트값 시드**(변경 전 100% 동일) ③관계수식=선언적 룰 테이블(산술 파라미터+분류 계층 catL/M/S+번들 매칭 룰[조건→구성품+수량비율], 기본=GAS 1:1) ④검증=**Golden master 회귀**(현 견적 snapshot vs 설정 계산 byte/금액 동일)+**Shadow 비교 IT**(하드코딩∥설정 diff 0)+운영 shadow 로깅(전환기). "설정화=하드코딩값 추출"이라 기능 차이 구조적 불가.

**기본 DC율(개발책임자 2026-06-17)**: 멀티 카테고리 공통 할인율(code.js 0.45=$L$2)도 카테고리별 설정. CategoryFormulaConfig(estimate_category→base_dc_rate, 기초값 시트). DC 체계(추정·확인필요): 멀티 일반=listPrice×(1−기본DC율), 변동DC=기본DC율 제외(납품가), 고정DC=품목 고정% override(대체/추가 확인). b4w11lmn2(F1-a) 완료 후 보강.

**🔑 종합견적서 vs 주문서 차이(개발책임자 2026-06-17)**: 전역/기본 DC율(45%)=초기값(변동 가능, 고정 아님). **종합견적서(estimate-app, 내부 영업 도구)=가격/DC 자유 설정**. **주문서(partner-order, 거래처 발주용)=설정 적용 가격 확정·임의 변경 X**(거래처가 보는 것이라 보호, server-side DcConfigClient 클라가격 무시 기존 구조 유지). 설정값 공용(카테고리/거래처/품목), **적용만 차이** — F5(estimate-app 자유)/F6(주문서 확정) 핵심.

**DC 계층 + 거래처DC 출처(개발책임자 2026-06-17)**: 주문서는 **거래처별DC 관리 메뉴(=dc-config-service DcConfig)**의 거래처별 DC율/할인액 불러와 적용(GAS는 노션 거래처정보 사용 → 우리는 dc-config DB 이관 완료 [[project_sheets_to_db_full_migration]], 기존 partner-order DcConfigClient 구조). **DC 계층**: ①기본DC율(카테고리 멀티 0.45, CategoryFormulaConfig 신규) ②거래처 DC율/할인액(dc-config DcConfig, 거래처별·노션 이관) ③고정DC(품목 %, Product.fixedDiscountRate) ④변동DC(품목 boolean=기본DC 제외). 주문서=거래처DC 적용, 종합견적서=기본+거래처+자유 조정.

**설정 UI 가독성(개발책임자 우려 2026-06-17, PM 제안)**: 한 설정창 과밀 방지 → ①기능별 메뉴 분리(견적품목 관리=품목별 핵심 컬럼[분류/고정DC/변동DC], 분류 관리=catL/M/S 계층 트리 CRUD, 가격/수식 설정=DC율/VAT/배분, 번들/옵션 설정=매칭 룰/수량) ②카테고리 탭(각 메뉴) ③점진적 노출(품목 행 핵심만, 상세='설정' 버튼→드로어/모달, 분류 대→중→소 단계).

**🔧 옵션 변경 설정 + 번들 매칭 수식 (개발책임자 2026-06-17, 변수 多 = 에픽 최대 난이도)**: 옵션 변경 시 적용되기 위한 설정 필요.
- 예) 판넬을 '공청판넬'로 설정 → 공청판넬이 선택되려면 **공청판넬 품목의 품목구분이 '판넬'인 경우 '공청판넬'로 특징(attribute) 설정**.
- 공청판넬도 **여러 개** → **해당 실내기에 맞는 공청판넬이 선택되는 매칭 수식 주의** (매칭 키=실내기 용량/모델/카테고리 ↔ 판넬, GAS 룩업 확인 필요).
- **리모컨 등도 동일** (실내기↔리모컨 매칭).
- **360판넬 = GAS처럼 '원형'/'사각' 2가지 따로 설정** 필요.
- **변수가 매우 많으므로 GAS 수식을 제대로 조사할 필요** (개발책임자 명시) → `tools/legacy-gas/` 번들 매칭/룩업 수식 깊이 정찰.
- 데이터 모델 후보: 품목 특징/attribute(판넬 종류=공청/일반/360[원형·사각]), 실내기↔옵션 매핑 테이블, 매칭 조건식.

**정찰 결과(2026-06-17)**: ①하드코딩 수식 27개(변동DC율 0.45·고정DC 6종·VAT·실내외 6:4/4:6·번들옵션 — dc-config-service+BundleExpander+partner-order). ②GAS 번들=시트 기본값(Row2)+사용자 선택, 실내기↔구성품=setModel 시트 관계+품명 정규식 분류. **GAS에 판넬변경/리모컨/유연호스/발통/분기관/360원형사각 옵션 多 존재**(실내기 선택 시 자동 끼워넣기[추천]만 없을 뿐, 옵션 자체는 있음). **그 옵션이 작동하려면 품목 세부설정(attribute) 필요** (개발책임자 정정 2026-06-17).

**착수 = F1**(개발책임자 선택): 품목 세부설정 + **고정DC%**(변동DC 옆, 품목별, 기초값=시트). **분류 정정(2026-06-17 개발책임자)**: ①카테고리별 **대분류(catL)/중분류(catM)/소분류(catS) 3단계 품목별 설정** ②**분류 사용자 추가/삭제 동적 + 계층(대분류→맞는 중분류→맞는 소분류)**. → 고정 enum 아닌 **동적 Classification 마스터(catL/catM/catS 3단계 계층, parent_id)**로(catL=판넬/리모컨/자재/실내기/실외기, catM=공청/360/유선·무선/유연호스, catS=360원형·사각/소형·중형·대형/원형발통·일자발 등). **EstimateCategory(홈멀티/싱글/상업멀티/구형)는 고정 유지**(슬1 동적화 폐기 결정), catL/catM은 동적(별개 2축).

**자동 수량 전개(개발책임자 정정 2026-06-17)**: 세트 수량 입력 → 구성품 자동 수량 채움 = **있음**(BundleExpander 세트→구성품 전개; 내 '자동 매칭 없음'은 '종류 추천 선택[공청/360]이 사용자 선택'이란 뜻·수량 자동 전개는 있음·표현 오류 사과). **실내기→판넬/리모컨/유연호스, 실외기→받침대/필터 등 부자재** 자동 선택+수량(adb50632 정찰 중). 이 수량 전개 규칙(실내기·실외기 종속 구성품 수량 비율)도 설정화 대상.

**모든 설정 페이지(카테고리)별(개발책임자 2026-06-17)**: 분류 catL/catM/catS·고정DC%·변동DC·옵션·수량 전부 카테고리(홈멀티/싱글중대형/상업멀티/구형)별 따로. **자동수량 정찰(adb50632) 결과**: BundleExpander `qty=setQty×defaultQty`(FOLLOW_SET), defaultQty=시트(싱글 1·상업 수량컬럼·유연호스 N), estimate-app `newCompQty=floor(setQty×defQ)` 동일. 설정화=defaultQty·수량비율 시트→DB(카테고리별)+실내외 6:4/4:6+옵션선별(판넬/리모컨/자재) 매칭.
