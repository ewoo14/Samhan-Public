2026-08-13 개발책임자 지시: **"삼성창고나 초월창고, 삼한창고는 같은 창고인거고, 이화창고와 상일물류 또는 상일창고도 같은 창고인거야."**

```
그룹 A   삼성창고 = 초월창고 = 삼한창고
그룹 B   이화창고 = 상일물류 = 상일창고
```

**왜 중요한가**: 삼성전자 「배송상황조회」 엑셀(가입고 업로드 소스)의 `고객명` 컬럼에는 사람이 아니라 **우리 창고명**이 들어온다. 그 이름이 우리 DB 창고와 1:1로 안 맞는다. 별칭을 모르면 같은 창고가 여러 건으로 갈라지거나 매칭 실패로 가입고가 통째로 누락된다.

**How to apply**: 엑셀 창고명 → DB 창고 매핑은 반드시 별칭 표를 거친다. 이름 문자열 일치로 조인하지 말 것.

## 회사PC 실측 (2026-08-13, `inventory_db.warehouses` 30건 중)

| DB code | DB name |
|---|---|
| `00003` | 삼성창고 (초월 무갑) |
| `11152` | 삼한창고 (무갑리) |
| `11155` | 2025-공항공사 초월창고 |
| `2` | 상일물류 |

🚨 **미해결**: 그룹 A 가 DB 에 **세 행**으로 존재한다. 셋 중 무엇이 가입고 대상 정본인지, 혹은 셋을 통합해야 하는지 **개발책임자 확인 필요**. 임의 선택 금지.
🚨 **"이화창고" 라는 이름의 창고는 DB 에 없다.** 엑셀에는 24건 들어온다. 별칭으로 `2 상일물류` 에 붙는 것으로 보이나 확정 필요.

⚠️ 집PC 에는 코드 `2`·`00003` 이 **없었다**([[feedback_home_office_seed_data_differs]]). 양 PC 시드가 다르니 수치는 그 PC 에서 다시 셀 것.
⚠️ `#1052` 가 코드 `2`·`00003` 을 "대응 불일치 2건" 으로 측정하며 QA 잔재로 의심했으나, 회사PC 에서는 `created_at` 이 나머지 창고 전부와 같은 `2026-05-22`(시드 일자)라 **QA 잔재가 아니라 정상 시드**다([[feedback_qa_rounds_pollute_shared_data]] 의 판별법 적용 결과).
