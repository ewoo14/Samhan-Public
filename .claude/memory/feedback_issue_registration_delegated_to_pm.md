# 🚨 이슈 생성 금지 (2026-08-07 개발책임자 · 현행)

> *"이슈가 왜 자꾸 늘어... **이슈 생성하지마**"*

하루에 **6건**을 열고 나서 받은 지적입니다(`#1111` `#1112` `#1113` `#1114` `#1116` + PR 4건).
자문 3개를 통과했다고 스스로 판단해도, **총량이 늘면 그것 자체가 문제**입니다.

## 지금 규칙

> 2026-08-07 재확인: *"앞으로는 **내가 요청하지 않으면** 신규 이슈 등록 금지."*

```text
🚫 gh issue create — **개발책임자가 요청할 때만**. PM 판단으로는 열지 않는다
✅ 발견은 **현재 PR 안에서 흡수**한다
✅ 흡수가 어려우면 **PR 코멘트·보고서에 기록만** 하고 남긴다
```

🔑 **기록과 등록은 다릅니다.** 잊지 않으려면 PR 코멘트·dev-report·TODO 에 적으면 됩니다.
   이슈는 *추적 단위를 새로 만드는 것*이라 백로그가 늘어납니다.

## 🆕 한 트랙(PR)이 **여러 이슈를 함께** 진행한다 (2026-08-07 개발책임자)

> *"현 트랙에 흡수 및 한 트랙에서 여러 이슈를 같이 진행할 수 있는지 확인해줘."*

기술적으로 가능하고, **그렇게 합니다.**

```text
PR 본문   연관 Issue: #A, #B, #C
머지 후   세 이슈를 모두 close (→ [[feedback_issue_close_after_pr]])
```

### 언제 흡수하고 언제 다음 트랙으로 미루나 — **타이밍이 유일한 기준**

```text
PR 이 머지 게이트에 근접   🚫 흡수하면 그 PR 이 늦어진다 → **다음 트랙에서 묶는다**
PR 이 초반·중반           ✅ 흡수한다
```

### 새 트랙을 열 때는 **표면으로 묶어서 하나로**

같은 파일·같은 화면·같은 테이블을 만지는 이슈를 따로 열면 **머지 충돌이 그 수만큼** 납니다.
실측: `#1117` S1 리베이스에서 `#1109` 테스트와 충돌해 수동 판단이 필요했다.

```text
묶는 기준   같은 파일 · 같은 화면 · 같은 테이블 · 같은 계약
🔑 이슈 번호가 여러 개여도 **트랙(PR)은 하나**다
```

## Why — 위임의 취지가 뒤집혔다

07-30 위임의 목적은 *"허락을 기다리는 병목 제거"* 였습니다. 그런데 실제로는
**PM 이 발견할 때마다 이슈를 만드는** 쪽으로 흘러 백로그가 순증했습니다.
07-30 문서에도 *"백로그 **순감**이 목표. 등록 수가 소진 수를 넘기면 위임의 취지에 어긋난다"*
라고 적혀 있었고, **그 조건이 실제로 깨졌습니다.**

## 이력

| 시점 | 규칙 |
|---|---|
| 2026-07-23 | 🚫 사전 허락 필수 |
| 2026-07-30 | ✅ PM 자율 등록 (허락 대기가 병목이라) |
| **2026-08-07 (현행)** | 🚫 **생성 금지 — 흡수 우선, 필요하면 먼저 질문** |

## 그대로 살아 있는 것 — 등록 전 자문 3개

권한이 생긴 것은 **판단을 생략해도 된다는 뜻이 아닙니다.** [[feedback_backlog_burndown_issue_bar]] 의 기준은 유지됩니다.

1. **한 파일 몇 줄인가?** — 그 정도면 현재 PR 에 흡수한다
2. **같은 표면에 열린 PR 이 있는가?** — 있으면 그 PR 에서 처리한다
3. **머지 게이트를 간헐 차단하는가?** — 그러면 별 이슈로 빼면 계속 되살아난다

하나라도 "예" 면 **흡수**입니다. 등록은 그 셋이 모두 아닐 때 — 다서비스·마이그레이션 규모이거나 별도 추적 단위가 필요할 때입니다.

## 함께 유지되는 것

- 🚨 **리뷰에서 나온 결함 fix 는 여전히 현재 PR 안에서** 처리합니다 → [[feedback_fix_in_current_pr_no_split]]. 이슈 등록 권한이 생겼다고 **적대검증 결함을 후속 이슈로 미루는 통로로 쓰면 안 됩니다.** 그게 이 위임의 유일한 악용 경로입니다.
- 등록한 이슈는 **PR 에 `연관 Issue: #N`** 으로 걸고 머지 후 close → [[feedback_issue_close_after_pr]]
- 백로그 **순감**이 목표입니다. 등록 수가 소진 수를 넘기면 위임의 취지에 어긋납니다

**Why:** 이슈 등록 허락을 기다리는 것 자체가 병목이었습니다. #984 슬2~5(순번코드→모델명 전환 잔여)처럼 *"현재 PR 에 넣으면 게이트가 다시 열리고, 빼면 허락을 기다려야 하는"* 교착이 실제로 생겼습니다.

**How to apply:** 자문 3개를 통과하면 바로 `gh issue create` 하고, **왜 흡수하지 않았는지**를 이슈 본문 첫 절에 적습니다. 관련 [[feedback_pm_autonomous_recommended_direction]] · [[feedback_pm_auto_merge_authority]]
