## 1. audit overlay 구성 요소

### 1-1. 기본 형태 — 단일 revision

화면 어떤 필드에 변경이 있을 때 우측에 다음과 같이 inline 표시됩니다.

```
메모  긴급 출고 요청 (오늘 마감 전)   ~~오전 배송 부탁드립니다~~   ● 김영업 14:32
```

| 시각 요소 | 의미 |
| --- | --- |
| 검정 굵은 텍스트 | 현재 값 (`긴급 출고 요청 (오늘 마감 전)`) |
| 취소선 + 회색 텍스트 | 변경 직전 값 (`오전 배송 부탁드립니다`) — 가장 최근 1건만 inline |
| ● 색상 dot | 수정자 식별 색상 (deterministic hash, [§1-3 참조](#1-3-색상-dot--deterministic-hash)) |
| 수정자 이름 | 풀네임 (`김영업`) — UUID 비공개 |
| `HH:mm` | 변경 시각 (오늘 = 시각만, 어제 이전 = `MM-DD HH:mm`) |

### 1-2. 작동 캡처

![수정 측 작동 — context A edit](https://github.com/ewoo14/SamhanLogis/raw/732e105/docs/qa/phase-12-step-2-slip-audit-overlay/working-audit-overlay-context-a-edit.png)

좌측은 김영업이 메모를 새 값으로 변경한 직후, 우측은 박영업 화면에 audit overlay 가 inline 으로 노출된 모습.

### 1-3. 색상 dot — deterministic hash

- 색상은 `userIdToColor(userId)` HSL hash 함수가 자동 결정합니다.
- 동일 사용자는 슬립/거래처가 달라져도 항상 같은 색상이 유지됩니다.
- "이 색은 김영업", "저 색은 박관리" 식으로 시각 학습이 가능합니다.
- 캐시/스타일 깨짐 시 `Ctrl + F5` 새로고침 (hash 는 deterministic 이라 색이 바뀔 일 없음).

기술 reference: `clients/web/design-system/src/utils/userColorHash.ts` (PR-H1 시드, PR-H2 부터 본격 사용).

## 2. 다중 revision 펼치기

같은 필드가 2회 이상 수정되었다면 inline 아래에 **[이력 N개 보기]** 버튼이 표시됩니다.

```
메모  익일 오전 배송으로 확정   ~~오후 배송으로 변경 요청~~   ● 박관리 16:48

[이력 3개 보기]   ◀ 클릭
```

클릭하면 가장 최근 → 과거 순으로 전체 revision 이 펼쳐집니다.

```
[이력 닫기]
  ┌───────────────────────────────────────────────────────┐
  │ ~~오전 배송 부탁드립니다~~              ● 김영업 14:32 │
  │ ~~(빈 값)~~                            ● 이작성 11:05 │
  └───────────────────────────────────────────────────────┘
```

### 2-1. 작동 캡처 — 다중 revision

![다중 revision 펼치기](https://github.com/ewoo14/SamhanLogis/raw/732e105/docs/qa/phase-12-step-2-slip-audit-overlay/working-audit-overlay-multi-revision.png)

위 캡처는 4 revision 이 누적된 슬립 메모 필드의 펼침 상태입니다. 좌측 일자/시각 / 가운데 색상 dot + 수정자 풀네임 / 우측 [복원] 드롭다운 ▾ (MASTER/MANAGER 만 표시) 의 일관 layout 확인.

## 3. 빈 값 (NULL → 신규 입력) 표시

### 3-1. 신규 입력 케이스

처음 입력된 필드는 이전 값이 NULL 입니다. audit overlay 는 `(빈 값)` 으로 가시화합니다.

```
배송지  서울 강남구 테헤란로 123 현장 사무소   ~~(빈 값)~~   ● 김영업 14:35
```

### 3-2. 입력 후 삭제 (값 → NULL) 케이스

```
배송지  (비어있음)   ~~서울 강남구 테헤란로 123 현장 사무소~~   ● 박관리 15:10
```

> NULL 표시는 한국어 `(빈 값)` 으로 통일. 영문/숫자/한글 길이 무관 동일 표시.

## 4. UUID 비공개 가드

화면 / DOM / network response 어디에도 사용자 UUID 가 직접 노출되지 않습니다.

| 위치 | 표시 |
| --- | --- |
| 화면 텍스트 | 풀네임 (`김영업`, `박관리`, `이작성`) |
| 색상 식별 | dot 색상 (`userIdToColor(userId)` 결과) |
| DOM `data-testid` | `audit-revision-{index}` 형태 (UUID 미포함) |
| DOM `aria-label` | `김영업이 수정함, 14:32` (한국어 + 풀네임) |
| network response | `userName` + `userColorHex` (UUID 는 BE 내부에서만 hash 변환) |

> 메모리 가드 `feedback_uuid_no_user_visibility.md` 의무. 모든 클라이언트 화면에서 UUID 노출 절대 금지.

## 6. 운영 변경 안내 (이전 vs PR-H2 / PR-H4c)

| 측면 | 이전 (Phase 12 이전) | 변경 (PR-H2 + PR-H4c) |
| --- | --- | --- |
| 수정 흔적 표시 | 마지막 수정자/시각만 (단일 컬럼) | 모든 revision 이력 audit log 누적 |
| 화면 표시 | "이력 보기" 별도 화면 진입 | 본문 필드에 inline overlay (취소선 + 색상) |
| 수정자 식별 | 텍스트 풀네임만 | 풀네임 + 색상 dot (시각 학습 가능) |
| 빈 값 처리 | 빈 행 (식별 어려움) | `(빈 값)` 한국어 명시 |
| UUID | 일부 화면에서 console / network 에 노출 | 전화면 UUID 비공개 가드 |
| 적용 범위 | slip-service 일부 화면만 | 17 service / 50+ desktop page + mobile-staff 일괄 |

## 7. FAQ

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| audit overlay 가 안 보임 | 해당 필드 수정 이력 0건 | 정상 — 0건 시 inline 숨김 |
| 동일 사용자인데 색상이 다르게 보임 | 캐시 / 스타일 깨짐 | `Ctrl + F5` (hash 는 deterministic) |
| 취소선 옛 값이 너무 길어 화면 깨짐 | 100자 초과 시 ellipsis (`...`) | 마우스 hover 시 tooltip 으로 전문 표시 / 또는 [이력 N개 보기] 클릭 |
| `(빈 값)` 이 자꾸 보임 | 신규 입력 필드 (NULL → 값) | 정상 — 의도된 표시 |
| [이력 N개 보기] 가 안 보임 | 수정 1회만 (다중 revision 없음) | 정상 — 단일 변경은 inline 만 |
| audit overlay 색상이 회색만 보임 | userColorHash 가 fallback 반환 (사용자 ID 누락) | IT 관리자에게 `userId` audit log 컬럼 점검 요청 |
| 모바일에서 색상이 안 보임 | mobile-staff 가 색상 dot 대신 작은 막대로 표시 | 정상 — mobile UX 변형 적용 |
| 수정자 풀네임이 `(알 수 없음)` 으로 보임 | 사용자 삭제 / 비활성 (탈퇴) | 정상 — 풀네임 영구 보존이 아닌 사용자 마스터 join 결과. 과거 풀네임 보존은 후속 PR 검토 |
