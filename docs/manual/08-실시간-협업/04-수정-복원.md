# 08-실시간-협업 / 04. 수정 복원 (Stage 4)

> ✅ **구현 상태** — Phase 12 step-2 (PR-H2) 복원 드롭다운 완성. PR-H4c 부터 audit overlay 적용 모든 항목에 동일 노출. **MASTER + MANAGER 권한 only**.
>
> **본 docs 는 무엇인가요?** — 실수로 잘못 수정한 항목을 과거 시점 값으로 되돌리는 절차와 권한을 안내합니다. 한국 일반기업회계기준 거래 보존 원칙에 따라 **복원 = 새 revision 추가** 형태로 구현 (이전 revision 절대 삭제 안됨).

---

## 대상 독자

- **MASTER** — 모든 항목 복원 가능
- **MANAGER** — 본인 부서 항목 복원 가능
- **WAREHOUSE / INVENTORY / SALES / DRIVER / ACCOUNTANT / MAINTENANCE / EXTERNAL** — 복원 권한 없음 (드롭다운 자체 hide). 복원이 필요하면 MASTER/MANAGER 에게 요청.
- 사전 준비: [02. 수정 이력 보기](02-수정-이력-보기.md), [03. 수정 횟수 카운트](03-수정-횟수-카운트.md)

---

## 이 매뉴얼에서 배울 내용

1. 복원 드롭다운 ▾ 위치와 표시
2. 복원 절차 (확인 다이얼로그 → 새 revision 추가)
3. 복원이 audit log 에 어떻게 기록되는지
4. 잠금 status 항목 복원 처리 (잠금 단계와의 상호작용)

## 1. 복원 드롭다운 표시

### 1-1. inline overlay 옆 ▾

각 revision 우측에 **▾** 드롭다운이 표시됩니다 (MASTER/MANAGER 만 노출, 그 외 ROLE 은 ▾ 자체 hide).

```
~~오후 배송으로 변경 요청~~   ● 박관리 16:48 ▾
                                       │
                                       ↓ 클릭
                          ┌────────────────────────┐
                          │ ↩ 이 시점으로 복원     │  ← rev 4 = 현재
                          │ ↩ rev 3 으로 복원      │
                          │ ↩ rev 2 으로 복원      │
                          │ ↩ 최초 값으로 복원     │
                          └────────────────────────┘
```

### 1-2. badge 클릭 모달의 복원 컬럼

[03. 수정 횟수 카운트](03-수정-횟수-카운트.md) §3-1 의 전체 audit log 표에서도 우측 [복원] 컬럼 ▾ 으로 동일 절차 가능.

## 2. 복원 절차

### 2-1. 단계별

1. inline overlay 또는 badge 클릭 모달에서 복원할 revision 선택 → ▾ 드롭다운 클릭
2. **확인 다이얼로그** 노출:
   ```
   +────────────────────────────────────────────────+
   │  복원 확인                                       │
   +────────────────────────────────────────────────+
   │  슬립 #2026-05-09-001 의 메모 필드를            │
   │  rev 2 (2026-05-09 14:32, 김영업) 시점 값으로  │
   │  복원하시겠습니까?                              │
   │                                                  │
   │  복원 후 값 :                                   │
   │  "오전 배송 부탁드립니다"                       │
   │                                                  │
   │  ※ 복원 = 새 revision 추가 (이전 revision      │
   │    영구 보존). 수정 N회 카운트 +1 증가.        │
   +────────────────────────────────────────────────+
   │  [ 취소 ]                  [ 복원 실행 ]         │
   +────────────────────────────────────────────────+
   ```
3. **[복원 실행]** 클릭 → BE `POST /audit/revisions/{slipId}/restore` (예시) → 새 revision 추가
4. 슬립 헤더 **수정 N회** 카운트 +1 증가
5. inline overlay 갱신 — 새 revision 이 가장 위에 추가
6. SSE 알림 — 같은 슬립을 보고 있는 모든 사용자 화면에 토스트:
   ```
   박관리가 슬립 #001 메모를 rev 2 시점으로 복원
   ```

### 2-2. 복원 후 audit log 표

복원 후 audit log 는 다음과 같이 누적됩니다 (rev 2 → rev 5 복원 예시).

```
rev # │ 시각              │ 수정자 │ 변경 필드          │ 비고
──────┼───────────────────┼────────┼────────────────────┼─────────────────────
6     │ 2026-05-09 17:30  │ 박관리 │ 메모               │ rev 2 시점 복원
5     │ 2026-05-09 16:48  │ 박관리 │ 메모               │
4     │ 2026-05-09 14:35  │ 김영업 │ 배송지, 검수지     │
3     │ 2026-05-09 14:32  │ 김영업 │ 메모, 결제조건     │
2     │ 2026-05-09 11:15  │ 이작성 │ 품목 수량 (3 → 5)  │
1     │ 2026-05-09 11:05  │ 이작성 │ (신규 작성)        │
```

> rev 2 자체가 사라지지 않고, rev 6 으로 새로 추가됨. "비고" 컬럼에 `rev N 시점 복원` 표시.

## 3. 권한 매트릭스

### 3-1. ROLE 별 복원 권한

| ROLE | 복원 가능? | 복원 범위 | 비고 |
| --- | --- | --- | --- |
| MASTER | ✅ | 모든 항목 / 모든 부서 | 회사 대표 (김미선) 또는 IT 책임자 1~2명 |
| MANAGER | ✅ | 본인 부서 항목만 | 영업팀장 / 창고팀장 / 회계팀장 |
| WAREHOUSE | ❌ | (드롭다운 자체 hide) | 복원이 필요하면 MANAGER 에게 요청 |
| INVENTORY | ❌ | (드롭다운 hide) | 동일 |
| SALES | ❌ | (드롭다운 hide) | 동일 |
| DRIVER | ❌ | (드롭다운 hide) | 동일 |
| ACCOUNTANT | ❌ (분개 제외) | 분개는 복원 불가 (역분개로만 처리) | [03-회계/01. 분개 입력](../03-회계/01-분개-입력.md) |
| MAINTENANCE | ❌ | (드롭다운 hide) | 동일 |
| EXTERNAL (외부 vendor) | ❌ | (드롭다운 hide) | 동일 |

> 자세한 ROLE 권한 매트릭스는 [00-시작하기/03. 역할별 권한](../00-시작하기/03-역할별-권한.md) §4-2 참조.

### 3-2. 부서 격리 (MANAGER)

MANAGER 는 본인 부서 항목만 복원 가능. 다른 부서 항목은 ▾ 자체가 표시되지 않습니다.

| MANAGER | 복원 가능 항목 |
| --- | --- |
| 영업팀장 (`MANAGER` + `dept = SALES`) | 슬립(SALES 발행) / 거래처 / 견적 / partner-order |
| 창고팀장 (`MANAGER` + `dept = WAREHOUSE`) | 슬립(WAREHOUSE 단계) / 입고 / 출고 / 재고 / 실사 |
| 회계팀장 (`MANAGER` + `dept = ACCOUNTING`) | 분개 (단, 분개는 복원 대신 역분개 권장) / 시산표 / 보고서 |
| 배차팀장 (`MANAGER` + `dept = DISPATCH`) | 카카오톡 배차 / 수동 배차 / 기사 배정 |

> MASTER 는 부서 무관 모든 항목 복원 가능.

## 4. 잠금 status 와 상호작용

### 4-1. 복원도 잠금 정책 적용

복원은 일반 수정과 마찬가지로 잠금 정책을 따릅니다. ([06. 잠금 정책](06-잠금-정책.md))

| 잠금 단계 | status | MASTER 복원 | MANAGER 복원 |
| --- | --- | --- | --- |
| 0차 (잠금 없음) | DRAFT / SAVED | ✅ 즉시 복원 | ✅ 즉시 복원 |
| 1차 잠금 | SENT / ACCEPTED / PROCESSING / REJECTED | ✅ 즉시 복원 | ✅ 즉시 복원 (자체 권한) |
| 2차 잠금 | INSPECTING / COMPLETED / SHIPPING / DELIVERED | ✅ 사유 200자 + 카테고리 | ❌ 불가 (MASTER 만) |
| 영구 잠금 | CONFIRMED / CANCELED | ❌ 불가 (역분개로만) | ❌ 불가 |

> 영구 잠금(CONFIRMED) 항목은 복원 ▾ 자체가 hide. 회계 역분개 또는 신규 슬립 발행으로만 처리.

### 4-2. 2차 잠금 복원 시 — MASTER 사유 입력

2차 잠금 (INSPECTING/COMPLETED/SHIPPING/DELIVERED) 항목 복원 시 MASTER 도 사유 200자 + 카테고리 (거래처 요청 / 재고 차질 / 법적 사유 / 기타) 입력 필수입니다.

```
+────────────────────────────────────────────────+
│  2차 잠금 복원 — 사유 입력                       │
+────────────────────────────────────────────────+
│  슬립 #001 (status: INSPECTING) — 메모 복원     │
│                                                  │
│  사유 (200자 이상 필수)                         │
│  ┌──────────────────────────────────────────┐ │
│  │ 거래처에서 검수 직전에 메모 변경 취소     │ │
│  │ 요청. 원래 메모로 복원 필요. 검수 절차    │ │
│  │ 영향 없음 확인.                            │ │
│  └──────────────────────────────────────────┘ │
│                                                  │
│  카테고리 (1개 선택)                            │
│  ○ 거래처 요청  ○ 재고 차질  ○ 법적 사유  ○ 기타│
+────────────────────────────────────────────────+
│  [ 취소 ]                  [ 복원 실행 ]         │
+────────────────────────────────────────────────+
```

> 사유 / 카테고리는 audit log 의 `restoreReason` / `restoreCategory` 컬럼에 영구 보존.

## 5. 운영 변경 안내 (이전 vs PR-H2)

| 측면 | 이전 (PR-H2 이전) | 변경 (PR-H2) |
| --- | --- | --- |
| 복원 가능? | ❌ 불가 (수동 재입력만) | ✅ 드롭다운 ▾ 클릭 |
| 권한 | (해당 사항 없음) | MASTER + MANAGER 한정 |
| 복원 방식 | (없음) | 새 revision 추가 (이전 revision 영구 보존) |
| 사유 입력 | (없음) | 1차 잠금 까지 미입력 / 2차 잠금 시 200자 + 카테고리 필수 |
| 영구 잠금 (CONFIRMED) | (해당 없음) | ❌ 복원 불가 — 역분개/신규 발행 |
| 알림 | (없음) | SSE 토스트로 같은 항목 보는 모든 사용자 통보 |

## 6. FAQ

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 복원 ▾ 가 안 보임 | 권한 부족 (WAREHOUSE/INVENTORY/SALES/DRIVER/ACCOUNTANT) | MANAGER 에게 복원 요청 |
| MANAGER 인데 ▾ 가 안 보임 | 다른 부서 항목 (부서 격리) | MASTER 또는 해당 부서 MANAGER 에게 요청 |
| ▾ 클릭했는데 옵션이 비어있음 | 단일 revision (1회 수정만 — 복원 대상 없음) | 정상 — 복원할 과거 시점 없음 |
| 복원 후 이전 revision 이 사라짐? | 사라지지 않음 — 새 revision 으로 추가됨 | 전체 audit log 펼치면 모든 과거 revision 보존 확인 가능 |
| 복원 후 다시 원래 값으로 되돌리고 싶음 | 또 한 번 복원 (rev N+1 → rev N) | 가능 — 다만 카운트 또 +1 증가 |
| CONFIRMED 슬립을 복원하고 싶음 | 영구 잠금 — 복원 불가 | 회계팀에 역분개 요청 (`accounting-service` `/journals/reverse`) 또는 신규 슬립 발행 |
| 2차 잠금 사유 입력했는데 [복원 실행] 회색 | 200자 미달 또는 카테고리 미선택 | 사유 200자 이상 + 카테고리 1개 선택 |
| 복원 알림 토스트가 안 옴 | SSE 연결 끊김 | `Ctrl + F5` 새로고침 |
| 복원 권한을 일시적으로 받고 싶음 | 권한 위임 (PR-H3 수정 요청 워크플로우와 별도 — 향후 검토) | 현재는 MASTER/MANAGER 본인이 직접 수행. 위임 PR 후속 검토 |
