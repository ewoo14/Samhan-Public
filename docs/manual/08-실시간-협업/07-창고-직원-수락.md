# 08-실시간-협업 / 07. 창고 직원 수락 (Stage 4)

> ✅ **구현 상태** — Phase 12 step-3 (PR-H3) 창고 직원이 수정 요청을 받는 mobile-staff + desktop UI 완성. PR-H3 commit `83cdf67` (mobile) + `f5ada0c` (desktop UX) 의무 시드.
>
> **본 docs 는 무엇인가요?** — 영업 직원이 출고 처리 단계 (`ACCEPTED`/`PROCESSING`/`INSPECTING`) 슬립의 수정 요청을 보낼 때, **창고 직원** (WAREHOUSE / INVENTORY ROLE) 이 받는 알림 / 검토 / 수락 / 거절 화면을 안내합니다.

---

## 대상 독자

- **WAREHOUSE / INVENTORY** — 출고 처리 중 슬립 수정 요청을 받는 창고 직원
- **MANAGER (창고팀장)** — 창고 직원이 수락/거절을 결정 못할 때 위임
- 사전 준비: [05. 수정 요청 워크플로우](05-수정-요청-워크플로우.md), [06. 잠금 정책](06-잠금-정책.md)

---

## 이 매뉴얼에서 배울 내용

1. 창고 직원이 받는 수정 요청 알림 (SSE 토스트 + 헤더 badge)
2. 대기 목록 (`/warehouse/edit-requests` 페이지) 사용법
3. 수락 / 거절 결정 기준 (재고 영향 / 검수 단계 영향)
4. mobile-staff 에서 수락 처리

## 1. 창고 직원 수락 권한 정책

### 1-1. 누가 수락 가능?

| 슬립 status | 잠금 단계 | 1차 수락자 | 비고 |
| --- | --- | --- | --- |
| `SENT` / `ACCEPTED` | 1차 | MANAGER (영업팀장) | 창고 직원은 알림만 받음 (참조) |
| `PROCESSING` / `INSPECTING` | 1차 / 2차 | **MANAGER (창고팀장)** + MASTER | 창고 직원이 picking/검수 중이라 영향 직접 평가 가능 |
| `COMPLETED` / `SHIPPING` / `DELIVERED` | 2차 | MASTER (창고팀장 검토 의견) | 재고 차감 / 출하 완료 — MASTER 결재 필수 |

> **WAREHOUSE / INVENTORY 직원 본인** 은 수락 권한 없음. 검토 의견만 첨부 가능. 최종 수락은 MANAGER (창고팀장) 또는 MASTER.

### 1-2. 검토 의견 첨부 (창고 직원의 역할)

창고 직원이 picking 중인 슬립의 수정 요청을 받으면, 본인 측에서 다음을 수행합니다.

1. 알림 토스트에서 [검토 의견 첨부] 클릭
2. 본 슬립의 picking 진행 상태 / 재고 영향 명시 (예: "이미 5개 picking 완료, 1개 추가 picking 시 재고 충분")
3. 의견 저장 → MANAGER (창고팀장) 화면에 자동 표시 → MANAGER 가 최종 수락/거절

## 2. 창고 직원 측 알림 화면

### 2-1. desktop — 우측 상단 토스트

영업이 수정 요청을 보내면 창고팀장 / 창고 직원 화면에 SSE 토스트 즉시 노출:

```
[ ⓘ 김영업이 슬립 #2026-05-09-001 수정 요청 ]
  현재 단계: PROCESSING (창고 picking 중)
  사유: 거래처에서 품목 수량을 4 → 6 으로 변경 요청
  [ 검토 ]
```

### 2-2. desktop — 헤더 badge

창고 페이지 (`/warehouse/*`) 우측 상단에 보류 요청 카운트 badge:

```
+──────────────────────────────────────+
│  창고 — 출고 처리                       │
│                       [ 🔔 검토 대기 3 ]│
+──────────────────────────────────────+
```

클릭 시 [§3. 대기 목록](#3-대기-목록---warehouseedit-requests-페이지) 으로 이동.

### 2-3. mobile-staff — 푸시 + 토스트

mobile-staff 앱은 푸시 (Expo Notifications) + 앱 내 토스트 동시 노출. ([08. 모바일 실시간 알림](08-모바일-실시간-알림.md))

```

│  검토 대기 목록 (3건)                                              │
+──────────────────────────────────────────────────────────────────+
│  슬립번호           │ 단계         │ 요청자 │ 사유 (요약)    │ 액션│
+─────────────────────┼──────────────┼────────┼────────────────┼─────┤

│  2026-05-09-005     │ INSPECTING   │ 박영업 │ 배송지 변경    │ 검토│
│  2026-05-09-008     │ ACCEPTED     │ 이영업 │ 결제조건 변경  │ 검토│
+─────────────────────┴──────────────┴────────┴────────────────┴─────┘
│  [ 새로고침 ]    [ 정렬: 단계 ▾ ] [ 필터: 본인 부서만 ▾ ]          │
+──────────────────────────────────────────────────────────────────+
```

| 컬럼 | 의미 |
| --- | --- |
| 슬립번호 | 비즈니스 식별자 (UUID 비공개) |
| 단계 | 현재 status (PROCESSING/INSPECTING 등) |
| 요청자 | 풀네임 |
| 사유 (요약) | 사유 첫 30자 (전문은 [검토] 클릭) |
| 액션 | [검토] 버튼 → 검토 다이얼로그 (§4) |

### 3-2. 정렬 / 필터

| 옵션 | 의미 |
| --- | --- |
| 정렬: 단계 | INSPECTING > PROCESSING > ACCEPTED 우선순위 |
| 정렬: 시각 | 가장 오래된 요청부터 |
| 필터: 본인 부서만 | MANAGER (창고팀장) 의 본인 부서 항목만 |
| 필터: 전체 | MASTER 만 가능 |

## 4. 검토 다이얼로그 — 수락 / 거절

### 4-1. 검토 다이얼로그 layout

[검토] 버튼 클릭 시 다이얼로그 노출 ([05. 수정 요청 워크플로우](05-수정-요청-워크플로우.md) §1-3 Step 4 와 동일):

```
+──────────────────────────────────────────────+
│  수정 요청 검토 — 슬립 #2026-05-09-001         │
+──────────────────────────────────────────────+
│  요청자  김영업 (영업1팀)                      │
│  요청 시각  2026-05-09 14:32                   │
│  현재 단계  PROCESSING (창고 picking 중)       │
│  잠금 단계  1차                                │
│                                                │
│  사유                                          │
│  ┌──────────────────────────────────────────┐ │
│  │ 거래처에서 품목 수량을 4 → 6 으로 변경   │ │
│  │ 요청. 재고 가능 확인 완료.                │ │
│  └──────────────────────────────────────────┘ │
│                                                │
│  수정 항목                                     │
│  • 품목/수량                                   │
│                                                │
│  창고 직원 검토 의견                           │
│  ┌──────────────────────────────────────────┐ │
│  │ HQ-001 창고 재고 8EA 보유 — 6EA picking  │ │
│  │ 가능. 추가 picking 5분 소요 예상.         │ │
│  └──────────────────────────────────────────┘ │
+──────────────────────────────────────────────+
│  [ 거절 ]                  [ 수락 (24h 해제) ]│
+──────────────────────────────────────────────+
```

### 4-2. 수락 / 거절 결정 기준

#### 수락 권장 케이스

- 변경 후 재고 충분 ([02-창고/03. 재고 조회](../02-창고/03-재고-조회.md) 에서 가용 재고 확인)
- picking 진행 5% 이내 (재작업 부담 적음)
- 거래처 confirm 명시 (사유에 "거래처 confirm" 키워드 + 영업의 음성/문자 첨부 가능)

#### 거절 권장 케이스

- 변경 후 재고 부족 → 분할 발행 권장
- picking 90% 이상 완료 (재작업 시 효율 저하)
- 검수 단계 진입 후 (이미 INSPECTING) — MASTER 결재 필요 → 거절 후 영업이 MASTER 에게 재요청 안내
- 사유가 모호 / 30자 미만 / 카테고리 미선택 (2차 잠금 시) → 거절 후 영업이 보강 후 재요청

### 4-3. 거절 사유 입력

[거절] 클릭 시 거절 사유 입력 다이얼로그 노출. 입력된 사유는 audit log `editRequestRejection` 컬럼에 영구 보존 + 영업 측 SSE 토스트 (빨강) 로 즉시 통보.

## 5. mobile-staff 수락 처리

### 5-1. mobile-staff 검토 화면

mobile-staff 앱 [검토 대기] 메뉴 (탭 하단) → 동일 layout 의 모바일 최적화 화면.

자세한 mobile UI는 [08. 모바일 실시간 알림](08-모바일-실시간-알림.md) §3 참조.

### 5-2. mobile vs desktop 권한 동등성

mobile-staff 수락 / 거절 = desktop 수락 / 거절과 동일 권한 / 동일 audit log 누적. 이중 인증 / 추가 확인 절차 없음 (PR-H3 commit `83cdf67`).

> **운영 의미** — 창고 직원이 picking 현장에서 즉시 수락 가능. desktop 으로 돌아갈 필요 없음.

## 7. FAQ

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 검토 대기 badge 가 0 인데 토스트가 옴 | 본인 부서 외 항목 (필터: 본인 부서만 적용 시) | 필터 [전체] 로 변경 (MASTER 만) 또는 다른 부서 MANAGER 가 처리 |
| [수락] 버튼이 회색 | 2차 잠금 — MASTER 권한 필요 | MASTER 에게 위임 또는 검토 의견 첨부 후 종료 |
| [거절] 후 영업이 다시 같은 사유로 요청 | 거절은 재요청 차단 안함 | audit log 누적 — 패턴 반복 시 MASTER 에게 보고 |
| picking 90% 완료인데 수정 요청 받음 | 영업이 진행 상황 모름 | 검토 의견에 picking 진행률 명시 후 거절 권장 |
| 검토 의견 입력 후 어디로 가나? | MANAGER (창고팀장) 화면에 자동 표시 + audit log 영구 보존 | MANAGER 가 본 의견 참조하여 최종 결정 |
| 모바일에서 검토 가능한가요? | 가능 — mobile-staff 동일 패턴 | [08. 모바일 실시간 알림](08-모바일-실시간-알림.md) |
| 슬립이 INSPECTING 인데 1차 잠금으로 표시? | (오류) | 정상 — INSPECTING 은 2차. 화면 새로고침 후 재확인 |
| 본인이 picking 중인 슬립의 요청을 본인이 수락 가능? | 권한 없음 (창고 직원) | MANAGER (창고팀장) 에게 검토 의견 첨부 후 위임 |
