# 08-실시간-협업 / 00. 실시간 협업 개요 (Stage 4)

> ✅ **구현 상태** — Phase 12 시리즈 완성 (PR-H1 SSE infra → PR-H2 audit overlay → PR-H3 잠금/요청 워크플로우 → PR-H4a shared module → PR-H4b BE 13 service 일괄 → PR-H4c FE 50+ page 일괄). 총 17 service / 50+ desktop page / mobile-staff 모두 동일 UX 패턴 적용.
>
> **본 매뉴얼 카테고리는 무엇인가요?** — 본 시스템(주) 삼한공조시스템 운영자가 Samhan Public 의 모든 화면(슬립/거래처/재고/세금계산서/배차/사용자 관리 등)에서 공통으로 만나는 **실시간 협업 5종 패턴** 을 안내합니다. 두 사람이 같은 화면을 동시에 보면서 한 명이 수정하면 다른 사람 화면이 즉시 갱신되고, 누가 언제 무엇을 바꿨는지 화면 안에서 한눈에 보이며, 잠금 상태에서는 권한자에게 정중히 수정 요청을 보낼 수 있습니다.

## 대상 독자

본 카테고리는 ROLE 무관, 모든 운영자가 1회 이상 읽기를 권장합니다. 특히:

- **신입 직원** (입사 1주차) — 화면 갱신/색상/취소선이 처음 보일 때 의미를 모르면 당황. 본 카테고리 1회 통독 권장.
- **MASTER / MANAGER** — 잠금 정책 / 수락-거절 기준 / 복원 권한 이해 필수.
- **WAREHOUSE / INVENTORY / SALES / DRIVER / ACCOUNTANT** — 자기 단계에서 잠금 상태일 때 수정 요청 절차 숙지.
- **IT 관리자** — SSE 연결 끊김 / 알림 미수신 트러블슈팅 안내 (06-트러블슈팅 보강 참조).

## Phase 12 사용자 가치 요약

### 1. 협업 마찰 해소

이전(Phase 12 이전) 운영에서는:

- 두 명이 같은 슬립을 동시에 열고 한 명이 저장하면, 다른 사람은 새로고침 전까지 변경 사실을 모릅니다. 새로고침을 잊으면 잘못된 정보로 추가 작업하다가 충돌(409 CONFLICT) 으로 실패.
- "어제 메모 누가 바꿨어요?" 묻기 위해 IT 관리자에게 audit log 조회 요청.
- 검수 단계 슬립을 거래처 요청으로 수정하려면 MANAGER 에게 전화로 부탁 → MANAGER 가 직접 화면 열어 수정.

Phase 12 이후:

- 한 명 저장 → 1초 이내 다른 사람 화면 자동 갱신 (SSE — `samhan.realtime.*` 이벤트).
- 화면 안에서 취소선 + 수정자 색상 + 이름 즉시 표시. audit log 조회 불필요.
- "이 슬립 메모 좀 바꿔주세요" 요청 → SlipEditRequestDialog 사유 입력 → MANAGER 토스트 알림 → [수락] → 본인이 24시간 내 직접 수정.

### 2. 한국 일반기업회계기준 거래 보존 원칙 준수

모든 수정은 audit log 에 영구 누적되며 삭제되지 않습니다. 복원(rollback) 도 "이전 revision 으로 복귀" 가 아니라 "새 revision 추가(이전 값과 동일한 새 row)" 형태로 누적됩니다. 감사/분쟁 시점에 100% 추적 가능.

### 3. UUID 비공개 가드 일관 적용

화면/DOM 속성 어디에도 사용자 UUID 가 노출되지 않습니다. 풀네임(`김영업`/`박관리`) + 색상 dot(deterministic hash) 만 표시. (메모리 가드 `feedback_uuid_no_user_visibility.md` 의무.)

### 4. 권한 표기 풀네임 일관

복원 / 수락 / 거절 권한 표는 모두 풀네임(`MASTER` / `MANAGER` / `WAREHOUSE` / `INVENTORY` / `SALES` / `DRIVER` / `ACCOUNTANT` / `MAINTENANCE` / `EXTERNAL`). 약어(M/M/D) 금지. (메모리 가드 `feedback_role_naming_full.md` 의무.)
