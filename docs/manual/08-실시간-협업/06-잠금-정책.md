## 1. 4단계 잠금 정의

### 1-1. 단계별 요약

| 잠금 단계 | 수정 경로 | 사유 | unlock 시간 | 수락자 |
| --- | --- | --- | --- | --- |
| **0차 (잠금 없음)** | 본인 + MANAGER+ 즉시 수정 | (불필요) | (해당 없음) | (해당 없음) |
| **1차 잠금** | 본인 → 권한자 요청 → MANAGER 수락 | 50자 권장 | 24시간 | MANAGER+ |
| **2차 잠금** | 본인 → 권한자 요청 → MASTER 수락 | **200자 + 카테고리 필수** | **1시간** | MASTER (MANAGER 검토 의견 가능) |
| **영구 잠금** | 회계 역분개 또는 신규 발행 | (수정 불가) | (수정 불가) | (해당 없음) |

### 1-2. 단계별 운영 의미

- **0차 (잠금 없음)** — 작성 / 임시 저장 단계. 자유 편집. 한국 일반기업회계기준 거래 보존 원칙은 적용되나 임시 단계라 모든 변경이 기본.
- **1차 잠금** — 처음 외부(거래처) 와 약속이 시작되는 단계 (`SENT` 발송 / `ACCEPTED` 접수). 변경 시 거래처 confirm 절차 필요. MANAGER 수락으로 운영 흐름 보호.
- **2차 잠금** — 재고 차감 / 검수 / 배송 진행 중. 변경 시 재고/회계 정합성 위험 큼. 200자 사유 + MASTER 결재로 강한 가드.
- **영구 잠금** — 회계 분개 완료 (`CONFIRMED`) 또는 취소 (`CANCELED`). 한국 일반기업회계기준 분개 변경 금지 원칙. 역분개 또는 신규 발행만 가능.

## 2. 슬립 11 status 잠금 매핑

| status | 잠금 단계 | 의미 |
| --- | --- | --- |
| `DRAFT` | 0차 | 작성 중 (저장 안된 상태) |
| `SAVED` | 0차 | 임시 저장 완료 |
| `SENT` | 1차 | 영업이 발송 — 창고 접수 대기 |
| `ACCEPTED` | 1차 | 창고 접수 완료 (재고 예약) |
| `PROCESSING` | 1차 | 창고 picking 중 |
| `INSPECTING` | 2차 | 검수 중 |
| `COMPLETED` | 2차 | 검수 완료 (재고 차감) |
| `SHIPPING` | 2차 | 출하 중 (트럭 적재) |
| `DELIVERED` | 2차 | 배송 완료 (서명 수신) |
| `CONFIRMED` | 영구 | 회계 분개 완료 — 정산 closed |
| `CANCELED` | 영구 | 취소 (soft delete) |
| `REJECTED` | 1차 | 거절 (재발행 가능) |

> 자세한 status 흐름은 [01-영업/03. 슬립 발행](../01-영업/03-슬립-발행.md) 참조.

## 3. 다른 service 잠금 매핑

### 3-1. 거래처 (`partner-service`)

| status / 조건 | 잠금 단계 | 의미 |
| --- | --- | --- |
| 신규 등록 (24시간 이내) | 0차 | 자유 편집 |
| 등록 완료 (24시간 이후) | 1차 | 사유 필요 |
| 신용 한도 초과 거래 진행 중 | 2차 | MASTER 결재 필수 |
| 폐업 처리 (`CLOSED`) | 영구 | 폐업 거래처는 수정 불가 |

### 3-2. 재고 (`inventory-service`)

| status / 조건 | 잠금 단계 | 의미 |
| --- | --- | --- |
| 입고 PENDING | 0차 | 자유 편집 |
| 입고 RECEIVED | 1차 | 입고 후 수정 필요 시 사유 |
| 출고 RESERVED | 2차 | 예약 후 수량 변경은 위험 |
| 출고 DEDUCTED | 영구 | 차감 완료 — 회계 영향 |

### 3-3. 세금계산서 (`tax-invoice-service`)

| status / 조건 | 잠금 단계 | 의미 |
| --- | --- | --- |
| 작성 중 (DRAFT) | 0차 | 자유 편집 |
| 발행 완료 (ISSUED) | **영구** | 한국 NTS 신고 후 수정 = 수정세금계산서 별도 발행 |
| 취소 (REVOKED) | 영구 | 한국 회계 표준 |

### 3-4. arologis 배차 (`arologis-service`)

| status / 조건 | 잠금 단계 | 의미 |
| --- | --- | --- |
| 신규 (NEW) | 0차 | 자유 편집 |
| 기사 배정 (ASSIGNED) | 1차 | 기사에게 통보 후 변경 |
| 출발 (DEPARTED) | 2차 | 운행 중 변경은 위험 |
| 완료 (COMPLETED) | 영구 | 배송 완료 — 슬립 DELIVERED 연동 |

### 3-5. 사용자 / 권한 (`user-service`)

| 변경 항목 | 잠금 단계 | 의미 |
| --- | --- | --- |
| 신규 사용자 등록 (24시간 이내) | 0차 | 자유 편집 |
| 풀네임 / 부서 / 연락처 | 1차 | 사유 |
| ROLE 변경 (MASTER ↔ MANAGER 등) | **2차** | MASTER 결재 + 200자 사유 |
| 비활성 (`disable`) | 영구 | 한 번 비활성 후 재활성은 신규 등록 권장 |

> 자세한 service 별 적용은 [09. 적용 범위](09-적용-범위.md) 참조.

## 4. 잠금 단계별 권한자 매트릭스

### 4-1. 수락 권한

| 잠금 단계 | 수락자 ROLE | 수락 범위 |
| --- | --- | --- |
| 0차 | (해당 없음) | 본인 + MANAGER+ 즉시 수정 |
| 1차 | MANAGER (본인 부서) / MASTER | MANAGER 는 본인 부서 항목만 |
| 2차 | MASTER 만 (MANAGER 는 검토 의견 첨부 가능) | 부서 무관 |
| 영구 | (수락 자체 불가) | 회계 역분개 / 신규 발행 |

### 4-2. 수정자 ROLE 별 가능 동작

| ROLE | 0차 자유 수정 | 1차 요청 | 2차 요청 | 영구 잠금 영향 |
| --- | --- | --- | --- | --- |
| MASTER | ✅ | ✅ (자체 수락) | ✅ (자체 수락) | 역분개 가능 |
| MANAGER (본인 부서) | ✅ | ✅ (자체 수락) | 요청만 (수락 = MASTER) | 역분개 회계팀 위임 |
| MANAGER (다른 부서) | (해당 항목 없음) | 요청만 | 요청만 | 위임 |
| WAREHOUSE / INVENTORY / SALES / DRIVER / ACCOUNTANT / MAINTENANCE / EXTERNAL | ✅ (본인 작성/처리 항목) | 요청만 | 요청만 | 위임 |

> 자세한 ROLE 별 권한은 [00-시작하기/03. 역할별 권한](../00-시작하기/03-역할별-권한.md) §4-2 참조.

## 5. unlock 시간 정책

### 5-1. 시간 분포

| 잠금 단계 | unlock 시간 | 만료 시 동작 |
| --- | --- | --- |
| 1차 | 24시간 (default) | 자동 잠금 + SSE 토스트 (`수정 가능 시간이 만료되었습니다`) |
| 2차 | 1시간 (default) | 자동 잠금 + SSE 토스트 |
| 영구 | (해당 없음) | (수정 불가) |

### 5-2. 환경변수 조정 (운영 변경)

배포 환경에 따라 unlock 시간 조정 가능 (PR-H3 chore commit `0e6785e` 환경변수화).

| 환경변수 | default | 의미 |
| --- | --- | --- |
| `SAMHAN_REALTIME_UNLOCK_LEVEL1_HOURS` | 24 | 1차 잠금 unlock 시간 (시간 단위) |
| `SAMHAN_REALTIME_UNLOCK_LEVEL2_MINUTES` | 60 | 2차 잠금 unlock 시간 (분 단위) |
| `SAMHAN_REALTIME_UNLOCK_REASON_LEVEL2_MIN_LENGTH` | 200 | 2차 잠금 사유 최소 글자 수 |

> production 환경 변경은 IT 관리자 / DevOps 와 협의 후 적용 권장.

## 6. 비즈니스 카테고리 (2차 잠금 전용)

### 6-1. 4 카테고리 정의

| 카테고리 | 의미 | 사용 예시 |
| --- | --- | --- |
| **거래처 요청** | 거래처가 변경을 명시 요청 | 검수 직전에 수량 변경 요청 / 배송지 변경 |
| **재고 차질** | 본 시스템 재고 부족으로 인한 변경 | 라인 분할 / 부분 출고 |
| **법적 사유** | 한국 일반기업회계기준 / 세법 / 거래법 준수 | 부가세 영세율 적용 / 면세 사업자 처리 |
| **기타** | 위 3가지에 해당 안되는 케이스 | (자유 사유 입력) |

### 6-2. 카테고리 선택 의무

2차 잠금 수정 요청 / 복원 시 4 카테고리 중 1개 선택 + 200자 사유 필수. audit log `lockReleaseCategory` 컬럼에 영구 보존.

> **운영 가치** — 카테고리별 통계로 어느 사유가 가장 빈번한지 분석 가능 (예: "거래처 요청" 60% → 거래처 confirm 절차 강화 필요). 후속 dashboard PR 후보.

## 8. FAQ

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 슬립이 잠겨있는데 단계가 어디인지 모름 | status 표시 확인 | 헤더의 status badge → §2 매핑 표 참조 |
| 거래처를 등록했는데 24시간 후에 잠금 | 1차 잠금 진입 (정상) | 사유 입력 후 [수정 요청] |
| 분개를 잘못 입력했는데 CONFIRMED 됨 | 영구 잠금 | 회계팀에 역분개 (`accounting-service` `/journals/reverse`) 요청 |
| 세금계산서 발행 후 변경하고 싶음 | 영구 잠금 (NTS 신고 후) | 수정세금계산서 별도 발행 ([03-회계/03. 세금계산서](../03-회계/03-세금계산서.md)) |
| 2차 잠금인데 사유를 짧게 쓰고 싶음 | 200자 강제 | 정책 — 200자 미달 시 [요청 보내기] 회색 |
| MANAGER 인데 다른 부서 항목 수락 불가 | 부서 격리 | MASTER 또는 해당 부서 MANAGER 에게 위임 |
| unlock 시간을 더 길게 받고 싶음 | 24h / 1h 고정 | 만료 후 다시 요청 (audit log 누적) |
| `SAMHAN_REALTIME_UNLOCK_*` 환경변수를 바꾸면? | 시스템 재시작 후 적용 | IT 관리자 / DevOps 와 협의 |
| 0차 단계인데 갑자기 잠금? | 다른 운영자가 status 전이 (SAVED → SENT) | 정상 — status 전이 시점에 1차 잠금 자동 진입 |
