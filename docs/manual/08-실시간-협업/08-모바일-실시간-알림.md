## 1. 알림 표시 3종

### 1-1. OS 푸시 알림 (Expo Notifications)

앱이 백그라운드 / 종료 상태일 때, OS 알림 센터에 푸시:

```
+──────────────────────────────────────+
│ Samhan Public                  지금  │
│ 김영업이 슬립 #001 수정 요청          │
│ 사유: 거래처에서 품목 수량 변경       │
│ 탭하여 검토                            │
+──────────────────────────────────────+
```

탭 시 앱 실행 → 해당 슬립 검토 화면 직접 진입.

### 1-2. 앱 내 토스트

앱이 포그라운드일 때, 화면 상단에 토스트 (3초 후 자동 사라짐):

```
+────────────────────────────────────────+
│ ⓘ 김영업이 슬립 #001 수정 요청          │
│   PROCESSING 단계 / [ 검토 ]            │
+────────────────────────────────────────+
```

### 1-3. 탭 헤더 badge

mobile-staff 하단 탭 [검토] 에 보류 카운트:

```
[ 슬립 ] [ 배차 ] [ 검토 (3) ] [ 설정 ]
                       ^^^
                       빨간 dot + 숫자
```

## 2. mobile-staff audit overlay 변형

### 2-1. 색상 dot → 작은 막대

좁은 화면(모바일) 에서 색상 dot 가 차지하는 공간 대신 **3px 세로 막대** 로 변형 표시:

```
[ 메모 ]
긴급 출고 요청 (오늘 마감 전)

│ ~~오전 배송 부탁드립니다~~  김영업 14:32
^
3px 색상 막대 (deterministic hash)
```

### 2-2. 다중 revision 펼치기 — 시트 (bottom sheet)

[이력 N개 보기] 탭 시 화면 하단에서 시트가 올라와 전체 revision 표시:

```
+──────────────────────────────────────+
│  슬립 #001 메모 — 전체 이력 (4)        │
+──────────────────────────────────────+
│ │ 익일 오전 배송으로 확정              │
│ │   박관리 16:48           [ 복원 ▾ ] │
│ │ ~~오후 배송으로 변경 요청~~          │
│ │   박관리 16:30           [ 복원 ▾ ] │
│ │ ~~오전 배송 부탁드립니다~~           │
│ │   김영업 14:32           [ 복원 ▾ ] │
│ │ ~~(빈 값)~~                          │
│ │   이작성 11:05                      │
+──────────────────────────────────────+
│              [ 닫기 ]                  │
+──────────────────────────────────────+
```

> 복원 ▾ 은 MASTER/MANAGER 만 표시. 그 외 ROLE 은 hide.

## 3. mobile 수정 요청 / 수락 처리

### 3-1. 수정 요청 보내기 (영업 직원 mobile)

slip 상세 → [✏ 수정 요청] 버튼 → 모바일 다이얼로그 (full-screen modal):

```
+────────────────────────────────────────+
│  ✕         수정 요청                    │
+────────────────────────────────────────+
│  슬립  #2026-05-09-001                  │
│  단계  PROCESSING (1차 잠금)             │
│                                          │
│  사유 (50자 권장)                        │
│  ┌────────────────────────────────────┐ │
│  │ 거래처에서 품목 수량을 4 → 6       │ │
│  │ 으로 변경 요청. 재고 가능 확인.   │ │
│  └────────────────────────────────────┘ │
│                                          │
│  수정 항목                               │
│  [ ✓ ] 품목/수량                         │
│  [   ] 메모                              │
│  [   ] 배송지                            │
│  [   ] 결제조건                          │
│                                          │
│              [ 요청 보내기 ]              │
+────────────────────────────────────────+
```

### 3-2. 수락 처리 (창고 직원 mobile)

[검토] 탭 → 대기 목록 → 슬립 탭 → 검토 화면 (full-screen modal):

```
+────────────────────────────────────────+
│  ✕   수정 요청 검토                     │
+────────────────────────────────────────+
│  요청자  김영업 (영업1팀)                │
│  요청 시각  2026-05-09 14:32             │
│  단계  PROCESSING / 잠금 1차              │
│                                          │
│  사유                                    │
│  거래처에서 품목 수량을 4 → 6 으로       │
│  변경 요청. 재고 가능 확인 완료.        │
│                                          │
│  수정 항목                               │
│  • 품목/수량                             │
│                                          │
│  창고 직원 검토 의견 (선택)              │
│  ┌────────────────────────────────────┐ │
│  │ HQ-001 재고 8EA 보유 — 6EA picking │ │
│  │ 가능. 추가 5분 소요 예상.           │ │
│  └────────────────────────────────────┘ │
+────────────────────────────────────────+
│  [ 거절 ]              [ 수락 (24h) ]   │
+────────────────────────────────────────+
```

### 3-3. 수락 후 SSE 토스트 (영업 측 mobile / desktop 동시)

영업 직원 mobile 화면에 즉시 토스트:
```
[ ✓ 수정 요청이 수락되었습니다 ]
   24시간 내 수정 가능
```

desktop 동시 수신 (만약 영업 직원이 desktop 도 켜둔 상태) → 두 곳 모두 동일 알림.

## 4. 권한 동등성 — mobile = desktop

### 4-1. 권한 매트릭스 동일

| ROLE | mobile-staff 권한 | desktop 권한 |
| --- | --- | --- |
| MASTER | 모든 항목 수락 / 복원 | 동일 |
| MANAGER (창고팀장) | 본인 부서 1차/2차 수락 | 동일 |
| WAREHOUSE / INVENTORY | 검토 의견 첨부 | 동일 |
| DRIVER | 배차 / 슬립 status 변경 / 서명 | 동일 |
| SALES | 본인 발행 슬립 수정 요청 | 동일 |

### 4-2. audit log 동일 컬럼

mobile 에서 보낸 요청 / 수락 / 거절 = desktop 과 100% 동일 audit log 컬럼 (`editRequestReason` / `lockReleaseCategory` / `editRequestRejection` 등). 이중 인증 / 추가 확인 절차 없음.

> **운영 가치** — 창고 직원이 picking 현장에서, 배송 기사가 트럭 안에서 즉시 수락 가능. desktop 으로 돌아갈 필요 없음.

## 5. mobile 특화 동작

### 5-1. 푸시 알림 ON/OFF

설정 → 알림 → 채널별 ON/OFF:

| 채널 | default | 비고 |
| --- | --- | --- |
| 수정 요청 (`edit.requested`) | ON | OFF 시 [검토] 탭 badge 만 |
| 수정 수락 (`edit.accepted`) | ON | |
| 수정 거절 (`edit.rejected`) | ON | 거절은 의무 통보 — OFF 권장 안함 |
| 만료 (`edit.unlock_expired`) | ON | |
| 삭제 (`delete.accepted`) | ON | |
| status 전이 (`*.transitioned`) | OFF (default) | 너무 빈번 — 필요한 사용자만 ON |

### 5-2. 오프라인 → 온라인 복귀

mobile-staff 가 오프라인 (지하철 / 산간) 상태에서 다시 온라인 복귀 시:

1. SSE 자동 재연결
2. 오프라인 동안 누적된 알림 일괄 수신 (최대 50건, 그 이상은 [검토] 탭에서 직접 조회)
3. 토스트는 일괄 알림 1건으로 압축 (`5개의 새 알림 — 탭하여 검토`)

### 5-3. 배터리 절약 모드 영향

OS 가 배터리 절약 모드일 때 mobile-staff 의 SSE 연결이 백그라운드 차단될 수 있습니다. 다음 조치 권장:

- mobile-staff 앱을 OS 의 "배터리 최적화 제외" 목록에 추가
- 푸시 알림 권한 항상 허용

## 6. 운영 변경 안내 (이전 vs PR-H4c)

| 측면 | 이전 (PR-H4c 이전) | 변경 (PR-H4c) |
| --- | --- | --- |
| mobile audit overlay | 없음 (모바일에서는 표시 안됨) | 색상 막대 + 다중 revision 시트 |
| mobile SSE 알림 | 일부 채널만 (배차) | 5채널 모두 (수정 요청 / 수락 / 거절 / 만료 / 삭제) |
| mobile 수정 요청 | desktop 만 가능 | mobile 동일 권한 / 동일 audit log |
| 푸시 알림 | 배차 알림만 | 5채널 모두 (채널별 ON/OFF 가능) |
| 적용 화면 | 일부 화면만 | mobile-staff 전체 화면 일괄 |

## 7. FAQ

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 푸시 알림이 안 옴 | OS 알림 권한 거부 / 배터리 절약 | 설정 → 알림 권한 ON + 배터리 최적화 제외 |
| 앱 내 토스트가 너무 자주 떠서 작업 방해 | 알림 채널 OFF 가능 | 설정 → 알림 → 채널별 OFF |
| 모바일에서 색상 dot 대신 막대로 보임 | 정상 — mobile UX 변형 | desktop 에서는 dot |
| [검토] 탭 badge 가 0 인데 푸시는 옴 | 본인 부서 외 항목 (필터: 본인 부서만) | 필터 [전체] 로 변경 (MASTER 만) |
| 오프라인 복귀 후 알림이 일부 누락 | 50건 초과 알림은 압축 (`5개의 새 알림`) | [검토] 탭에서 직접 조회 |
| mobile 에서 복원 ▾ 가 안 보임 | 권한 부족 (WAREHOUSE/INVENTORY) | MASTER/MANAGER 에게 요청 |
| 푸시 알림 시각이 정확하지 않음 | OS 알림 큐 지연 (5~30초) | 정상 — 앱 내 토스트는 1초 이내 |
| 배차 알림은 오는데 수정 요청 알림은 안 옴 | 채널 OFF (default 이전 상태) | 설정 → 알림 → "수정 요청" ON |
| mobile 에서 수락한 후 desktop 에 반영 시간? | 즉시 (동일 SSE 채널) | 1초 이내 |
