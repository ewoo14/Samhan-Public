## 1. 현재 우회 방법 (P1-5 admin 폼 부재 시)

### 1-1. 우회 1 — 카카오톡 형식으로 직접 작성

전용 admin 폼이 부재하므로, 카카오톡 메시지 형식 ([01. 카카오톡 배차](01-카카오톡-배차.md) §1) 으로 직접 작성하여 `POST /admin/arologis/dispatches` 호출.

```
8일착 야상입니다
1. 본사창고
-서울 강남구 역삼동(현대공조-501)10시
1톤
```

→ `POST /admin/arologis/dispatches` body:
```json
{ "kakaoText": "8일착 야상입니다\n1. 본사창고\n-서울 강남구 역삼동(현대공조-501)10시\n1톤" }
```

→ 응답 `{ "dispatchId": "..." }`.

### 1-2. 우회 2 — backend 직접 INSERT (P0-5 사용자 UI 부재 패턴 동일)

개발팀에 SQL 요청. 권장 X — audit trail 누락 위험.

```sql
INSERT INTO dispatches (id, dispatch_date, dispatch_type, raw_kakao_text, ...)
VALUES (gen_random_uuid(), '2026-05-08', 'NIGHT', '(수동입력)', ...);
```

> ⚠️ Soft Delete / BaseEntity audit 7 필드 누락 → BE-2 가드 위반. 운영팀 우회만, 정식 입력은 §1-1 권장.

## 3. 정차 상태 갱신

### 3-1. StopStatus 7 단계

| 상태 | 의미 | 운영 | 트리거 |
| --- | --- | --- | --- |
| **UNPARSED** | 카톡 파싱 실패 (보정 대기) | admin | parser |
| **PENDING** | 배차 직후 (대기) | 자동 | DispatchService.create |
| **DISPATCHED** | driver 배정 완료 | 자동 | autoMatch / assignDriverManual |
| **EN_ROUTE** | 출발 (이동 중) | 모바일 / admin | driver-app GPS / admin |
| **ARRIVED** | 거래처 도착 | 모바일 / admin | driver-app / admin |
| **COMPLETED** | 서명 완료 (정상) | 자동 | driver-app sign |
| **FAILED** | 미배달 / 부재중 | admin | admin 보정 |

### 3-2. admin 정차 상태 변경

`PUT /admin/arologis/dispatches/{id}/vehicles/{seq}/stops/{stopSeq}/status` body `{ "status": "ARRIVED" }`.

화면 (P1-5 fix 시) → 정차 라인 우측 [상태 변경] → 드롭다운 → 저장.

![정차 상태 변경](../screenshots/05-arologis/02-stop-status-change.png)

> 모바일 driver-app 의 sign 호출이 자동으로 COMPLETED 갱신하므로, admin 보정은 예외 상황 (서명 누락 / 부재중 등) 만.

## 4. Dispatch Soft Delete

`PUT /admin/arologis/dispatches/{id}/delete` 호출. BaseEntity.markDeleted 적용 (audit 보존).

UI (P1-5) → list 화면에서 row 우측 [삭제] → 확인 dialog → soft delete.

> ⚠️ Soft Delete 후 list 응답에서 자동 제외. DB 에는 `deleted_at` / `deleted_by` 만 채워지고 row 보존. 복원은 개발팀 SQL.

## 5. 권한 + 운영자 시점 ROLE

| 작업 | MASTER | MANAGER | SALES | DRIVER |
| --- | :-: | :-: | :-: | :-: |
| Dispatch 저장 | ✅ | ✅ | ❌ | ❌ |
| 정차 상태 갱신 | ✅ | ✅ | ❌ | ❌ (자동만) |
| 수동 driver 배정 | ✅ | ✅ | ❌ | ❌ |
| Soft Delete | ✅ | ✅ | ❌ | ❌ |

> 별도 `DISPATCH` ROLE 은 backlog. 현재는 MANAGER 또는 MASTER 만 admin 호출 가능 (`@PreAuthorize("hasAnyRole('MASTER','MANAGER')")`).

## 6. 트러블슈팅 + FAQ

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `kakaoText 필수` 400 | body 미입력 | `{"kakaoText": "..."}` 형식 확인 |
| `헤더 라인 파싱 실패` 400 | `8일착 야상입니다` 누락 | 첫 줄 헤더 추가 후 재호출 |
| 톤수가 모두 `1톤` | 톤수 라인 누락 | 차량 그룹 끝에 `1톤` 등 추가 |
| Dispatch 저장 후 list 에 안 보임 | 날짜 필터 다름 | `GET /admin/arologis/dispatches?date=2026-05-08` 명시 호출 |
| 같은 Dispatch 두 번 저장됨 | idempotency 부재 | 운영자가 list 조회 후 중복 → soft delete |
| 정차 상태 갱신 시 404 | seq / stopSeq 불일치 | `GET /admin/arologis/dispatches/{id}` 로 정확한 sequence 확인 |
| `403 Forbidden` | SALES / DRIVER ROLE | MASTER / MANAGER 만 admin endpoint 호출 가능 |
| Soft Delete 후 복원 필요 | UI 부재 | 개발팀에 `UPDATE dispatches SET deleted_at=NULL WHERE id=...` SQL 요청 |
