## 2. 자동 매칭 (autoMatch)

### 2-1. 동작 흐름

```
[배차 담당]                          [arologis-service]
[자동 매칭] ────→ POST /admin/arologis/dispatches/{id}/auto-match
                          │
                          ↓ for each Vehicle (PENDING 만)
                       vehicle.markMatching() (status = MATCHING)
                          │
                          ↓
                       DriverMatcher.match(vehicle, stops)
                          ┌────────────────┬────────────────┐
                          ↓                ↓                ↓
                    MockDriverMatcher  InsungQuick      (장기 backlog)
                    (dev/test)         DriverMatcher    KakaoBotMatcher
                          │                │
                          └────────┬───────┘
                                   ↓ DriverMatchResult
                       { driver: Optional<Driver>,
                         source: MatchSource,
                         externalRefId: String }
                          │
                          ↓ 매칭 성공 시
                    vehicle.assignDriver(driverId, source, externalRefId)
                    matched++
                          │
                          ↓ NotificationClient.send (PUSH)
                    "신규 배차 매칭 — 차량 #1 (1톤) 배정"
                          │
                          ↓ 응답
                    { totalVehicles: 13, matched: 9 }
```

### 2-2. 매칭 score 기준 (Mock 단계)

`MockDriverMatcher` 는 dev / test 용으로 단순 score:

| 항목 | 가중치 | 비고 |
| --- | :-: | --- |
| 차량 톤수 ↔ driver vehicleType 일치 | 0.4 | 1톤 ↔ 1톤 = 만점, 1톤 ↔ 2.5톤 = 0 |
| INTERNAL 우선 | 0.3 | INTERNAL = 만점, EXTERNAL = 0 |
| appInstalled = true | 0.2 | INTERNAL 만 가능 |
| 기본 점수 | 0.1 | (활성 driver 모두) |

`InsungQuickDriverMatcher` 는 W10-2 시점에 인성데이타 vendor API score 사용 (거리 / 가격 / 평점).

### 2-3. 매칭 실패 (`matched < totalVehicles`)

원인:
- 모든 driver 가 다른 dispatch 에 이미 배정 (capacity 부족)
- 차량 톤수에 맞는 driver 가 없음 (예: 5톤 dispatch 인데 INTERNAL 1톤 / 2.5톤 만)
- DriverMatcher 가 placeholder (UnsupportedOperationException → log warn + fail-soft)
- 외부 vendor API 일시 장애 (Insung — fail-soft, 다음 매칭에서 재시도)

매칭 실패 차량은 PENDING 으로 복귀하지 않음 (MATCHING 유지) — 운영자가 수동 배정 필요.

## 3. 수동 배정 (assignDriverManual)

### 3-1. 절차

매칭 실패한 차량 또는 특정 driver 지정 필요 시:

```
POST /admin/arologis/dispatches/{id}/vehicles/{seq}/assign-driver
Body: { "driverCode": "DRV-2026-001" }
```

응답:
```json
{ "dispatchId": "...", "driverCode": "DRV-2026-001" }
```

서버 처리:
1. driverCode 로 Driver lookup → 없으면 404
2. vehicle 의 dispatchId + sequence lookup → 없으면 404
3. `vehicle.assignDriver(driverId, MatchSource.MANUAL, null)` — MatchSource = MANUAL 로 audit
4. 알림 push 는 보내지 않음 (수동 배정은 운영자가 직접 driver 에 통보)

### 3-2. UI (P1-5 fix 후)

차량 row 우측 [기사 배정] → driver 검색 dialog (driverCode / 이름 / 전화) → 선택 → 저장.

![수동 driver 배정 dialog](../screenshots/05-arologis/03-manual-assign.png)

> ⚠️ 현재 P1-5 미구현 — UI 도착 시 fix. 그 전까지는 backend API 직접 호출 또는 개발팀 우회.

## 4. 외부 vendor (인성데이타 퀵프로그램) — W10-2 시점

### 4-1. 통합 개요

- 인성데이타 = 한국 최대 퀵서비스 vendor (5만 프리랜서 풀)
- W10-2 시점에 `InsungQuickDriverMatcher` 활성 + REST 통합
- 본 어플 driver 가 부족할 때 외부 풀에서 자동 매칭

### 4-2. 통합 흐름

```
arologis autoMatch
  ↓
  INTERNAL driver 매칭 시도 (1순위)
  ↓ 실패
  InsungQuickDriverMatcher.match
    ↓
    Insung API call (POST /insung/dispatch/match)
    ↓
    응답 = { driverId: "INSUNG_xxx", score: 0.85, eta: "10분" }
    ↓
  arologis Driver 테이블에 EXTERNAL_INSUNG_QUICK 으로 자동 INSERT (idempotent)
  ↓
  vehicle.assignDriver(insungDriverId, EXTERNAL_INSUNG_QUICK, "INSUNG_xxx")
```

### 4-3. 운영자 시점

- 자동 매칭 결과의 driver 가 EXTERNAL_INSUNG_QUICK 인 경우 → 인성 vendor 가 자체 채널로 driver 에 통보
- arologis 자체 push 알림은 송신되지 않음 (`NotificationClient.send` skip — `appInstalled=false` 가드)
- 정차 상태 갱신은 인성 vendor webhook 또는 admin 수동 (P1-5 fix 후)

> 자세한 인성 vendor API: 개발팀 W10-2 PR 참조.

## 5. 배정 후 driver 시점 흐름

### 5-1. INTERNAL driver (본 어플)

```
1. 어플 push 알림 수신 — "신규 배차 매칭 — 차량 #1 (1톤) 배정"
2. 어플 진입 → 오늘의 배정된 dispatch 목록 (`GET /driver-app/arologis/dispatches/today`)
3. 차량 sequence + tonnage + status 표시
4. GPS 위치 보고 자동 (`POST /driver-app/arologis/locations`)
5. 정차 도착 → 거래처 서명 수신 (`POST /driver-app/arologis/dispatches/{id}/vehicles/{seq}/stops/{stopSeq}/sign`)
6. W10-4 SlipResolver → slip-service 양쪽 저장 (slipBridged: true)
```

자세한 driver 어플 사용법: [04-모바일/01. 기사 앱](../04-모바일/01-기사-앱.md) *(Stage 3 예정)*.

### 5-2. EXTERNAL driver (INSUNG / KAKAO / SMS)

- 본 어플 비사용
- 인성 자체 어플 또는 카톡 / SMS 로 배차 정보 전달
- 정차 상태 / 서명 = admin 수동 (P1-5 fix 후) 또는 W10-4 인성 webhook (장기 backlog)

## 7. FAQ + 트러블슈팅

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 자동 매칭 0건 | DriverMatcher = placeholder (UnsupportedOperationException) | `application.yml` `app.arologis.matcher.active` 설정 확인 / 개발팀 |
| 매칭은 됐는데 driver 어플 push 미수신 | EXTERNAL driver — push 채널 없음 | INSUNG / KAKAO 는 외부 채널 / 본 시스템에서 SMS 발송 안함 |
| INTERNAL driver 인데도 push 미수신 | NotificationClient 비활성 / appUserId null | DriverSeeder 의 `appUserId` 필드 채움 (현재 모두 null — auth-service 통합 시 매핑) |
| 수동 배정 시 `driver 미존재` 404 | driverCode 오타 | `GET /admin/arologis/drivers` 로 정확한 코드 확인 |
| `vehicle 미존재` 404 | sequence 오타 | `GET /admin/arologis/dispatches/{id}` 로 vehicle sequence 확인 |
| 매칭 후 vehicle.status 가 MATCHING 그대로 | 매칭 실패 (driver 없음) → assignDriver 미호출 → MATCHING 유지 | 수동 배정 → ASSIGNED 또는 PENDING 수동 복귀 (개발팀 SQL) |
| 같은 driver 가 여러 dispatch 에 배정됨 | capacity 가드 부재 | 운영자 수동 모니터링 (Phase 11 후 P3 capacity 관리) |
| EXTERNAL_INSUNG_QUICK driver 의 정차 상태 갱신 안됨 | 인성 webhook 미통합 (W10-2 backlog) | admin 수동 갱신 (P1-5 fix 후) |
| `app.arologis.seed-test-data=true` 안 했는데 시드 driver 가 보임 | 이전 dev 환경에서 seed 적용된 후 개발 DB 가 살아있음 | 개발 DB reset 또는 운영 DB 분리 확인 |
