## 1. 영업 모바일 개요

### 1-1. 1개 어플 통합 (mobile-staff)

영업 직원 + 배송 기사가 **같은 mobile-staff 어플** 을 사용합니다 (Phase 10 W10-3 사용자 결정).

| mode | 화면 | 대상 | 본 매뉴얼 |
| --- | --- | --- | --- |
| **estimate** (default) | legacy estimate-app v2 WebView | 영업 직원 (SALES) | **본 매뉴얼** |
| **driver** | RN native 4 화면 | 배송 기사 (DRIVER) | [01. 기사 앱](01-기사-앱.md) |

### 1-2. estimate mode = WebView

영업 mode 의 화면 = **react-native-webview 단일 screen** 으로 legacy estimate-app v2 (Node.js + Express + EJS) 를 그대로 임베드합니다. RN 측 native UI 코드는 SafeAreaProvider + StatusBar + WebView wrapper 만 책임.

> legacy estimate-app v2 = Apps Script `Code.js` 18,614 라인 1:1 보존 (PR #60 회고 / `clients/web/estimate-app/views/index.ejs`).

### 1-3. legacy 보존 이유

- Apps Script 18,614 라인의 RPC 11종 + 견적 작성 로직을 native RN 으로 신규 작성하면 20주+ 추가 (옵션 B2)
- 사용자 결정 (2026-05-07) — Phase 11 production 까지는 legacy 보존 + WebView wrapper 만 활성
- Phase 11 후 native UI 마이그레이션 옵션 B2 정식 검토

## 2. 영업 mode 진입

### 2-1. mode 토글 (우상단)

mobile-staff 앱 진입 시 우상단의 mode 토글 → [estimate] (default) 선택.

![mode 토글 — estimate 선택](../screenshots/04-모바일/03-sales-mode-toggle.png)

> SALES 권한만 보유한 직원은 estimate mode 가 default 로 자동 선택됩니다 (driver 토글 비활성).

### 2-2. WebView 자동 진입

estimate mode 선택 즉시 `EstimateWebViewScreen` 이 표시됩니다.

| 환경 | WebView source URL |
| --- | --- |
| **dev** (`__DEV__ === true`) | `http://localhost:5183/` |
| **prod** | `https://estimate.samhan-air.com/` |
| **override** | `EXPO_PUBLIC_ESTIMATE_APP_URL` 환경변수 |

### 2-3. 자동 로그인 (Apps Script 호환 흐름)

WebView 진입 직후 legacy `Code.js` line 16,495 의 `checkUserAuth(USER_EMAIL)` 가 자동 호출 → iam-service `/api/v1/auth/me?email=` (mock fallback) → 영업 직원 식별.

> token 은 WebView 안 cookie / sessionStorage 에 저장 — RN 측 미관여 (RN 인증 코드 0줄). Apps Script `google.script.run` shim 이 모든 RPC 11종을 처리.

## 4. 견적 작성 → 주문 → 슬립 흐름 (모바일)

### 4-1. Step 1 — 거래처 선택

[전표작성] 메뉴 → 거래처 input → 자동완성 선택 → 거래처 마스터 정보 자동 채움.

### 4-2. Step 2 — 카테고리 진입 + 라인 추가

[페이지 메뉴] → [홈멀티] / [상업멀티] 등 → 라인 grid 에서 모델 선택 → 수량 입력 → [추가].

### 4-3. Step 3 — 견적서 미리보기

[페이지 메뉴] → [견적서(기본)] / [견적서(세트상세)] → 견적서 인쇄 양식 미리보기 (P0-4 진행중 — 인쇄 양식 단번 완성 금지, 3~5회 iteration).

### 4-4. Step 4 — 저장 + 발송

[저장] → 임시 저장 → [발송] → SMS/카카오톡 발송 (Aligo 연동).

### 4-5. Step 5 — 거래처 주문 자동 변환

거래처가 발송된 견적서 링크 진입 → 확정 → [01-영업/05. 거래처 주문](../01-영업/05-거래처-주문.md) 의 자동 변환 흐름 → 슬립 발행 자동 처리.

### 4-6. Step 6 — 슬립 status 흐름

자동 변환된 슬립은 [01-영업/03. 슬립 발행](../01-영업/03-슬립-발행.md) §6 의 11 status workflow 진입.

## 5. mode 토글 (영업 ↔ 기사)

영업 직원 + 배송 기사 권한 양쪽 보유 시 (예: 소형 운영, 영업이 직접 배송) 우상단 토글로 mode 변경 가능.

| 토글 | 화면 |
| --- | --- |
| **estimate** | 본 매뉴얼 — 영업 견적 WebView |
| **driver** | [01. 기사 앱](01-기사-앱.md) — RN native 4 화면 |

> 두 mode 는 같은 JWT 를 공유. 토글만 변경 → 즉시 화면 전환 (재로그인 불필요).

## 8. legacy 화면 안내 (사용자 시각)

### 8-1. legacy 화면이 데스크탑과 동일한가?

거의 동일합니다. legacy `views/index.ejs` 의 `mobile-mode` toggle 만 자동 활성되어 4 카드 grid → 1열 stack, 컬럼 일부 hide / show 만 변경. **메뉴 / 작성 흐름 / 견적서 양식은 100% 동일.**

### 8-2. desktop 에서 작성한 견적이 모바일에서 보이는가?

네. 같은 backend (estimate-app v2 `server.js` + iam-service) 를 공유하므로 `[저장내역]` 메뉴에서 즉시 조회 가능.

### 8-3. 모바일에서 작성한 견적이 desktop 에서 보이는가?

네. 양방향 동일.

### 8-4. 모바일 전용 기능이 있는가?

페이지 메뉴 dropdown (▼ 버튼) 이 모바일 전용 진입점입니다. desktop 에서는 화면 상단 가로 메뉴 bar 로 노출.

## 9. 자주 묻는 질문 + 트러블슈팅

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| WebView 가 빈 화면 | dev server 미가동 / 네트워크 끊김 | `curl http://localhost:5183/healthz` 확인 또는 IT 관리자 문의 |
| 로그인이 안 됨 | iam-service 비활성 / mock fallback 도 실패 | IT 관리자 문의 |
| mobile-mode 활성 안 됨 (4 카드 그대로) | viewport width > 768px (태블릿 등) | 정상 동작 — 태블릿은 desktop 모드 사용 |
| 페이지 메뉴 ▼ 버튼이 안 보임 | mobile-mode 비활성 (viewport 큰 경우) | 본 §8-1 — 데스크탑 메뉴 bar 사용 |
| 다크모드 토글 안 먹힘 | legacy `views/index.ejs` 의 dark-mode CSS 일부 미완 | 라이트모드 사용 권장 (개선 backlog) |
| 견적서 인쇄가 깨짐 | P0-4 진행중 — 인쇄 양식 iteration 중 | 디자이너에게 화면 캡처 + 의견 전달 |
| `[발송]` 후 SMS 안 옴 | Aligo 연동 환경 변수 미설정 / 잔액 부족 | IT 관리자 문의 |
| `[저장]` 후 사라짐 | 자동 로그아웃 (5분 idle) — 미저장 분실 | 작성 중에는 화면 활성 유지 |
| RN 뒤로가기 즉시 앱 종료 (Android) | WebView history 끝 | 정상 — 페이지 메뉴 [닫기] 권장 |
| driver 토글이 안 보임 | DRIVER 권한 미보유 (정상) | SALES 단독은 estimate 만 사용 |
| WebView 폰트가 깨짐 | Pretendard 미배치 / CDN 차단 | IT 관리자 문의 (graceful guard 활성) |
| 카카오톡 견적 발송 후 거래처 주문 자동 변환 안 됨 | order-app v4 / iam-service flow 장애 | [01-영업/05. 거래처 주문](../01-영업/05-거래처-주문.md) §FAQ 참조 |
