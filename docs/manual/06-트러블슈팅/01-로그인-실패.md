# 06-트러블슈팅 / 01. 로그인 실패 (Stage 3)

> **대상 독자**: 모든 직원 + IT 관리자
> **소요 시간**: 5분 (자가 진단 후 IT 관리자 escalation 필요 시 별도)
> **연관 매뉴얼**: [00-시작하기/01. 로그인](../00-시작하기/01-로그인.md)
> **연관 누락**: P0-2 (비밀번호 재설정 7건 미구현 — 본 매뉴얼에서 안내)

---

## 이 매뉴얼에서 다루는 증상

1. **비밀번호 분실** — `/auth/password/reset` 미구현 → IT 관리자 우회
2. **5회 실패 시 계정 잠금** — `failed_login_attempts` 컬럼 부재 → 잠금 자체 미구현
3. **권한 부족 (403)** — 메뉴는 보이는데 클릭 시 거부 → ROLE 매트릭스 확인
4. **JWT 만료 / 401** — token 자동 갱신 실패 → 재로그인
5. **백엔드 500 / Eureka 비활성** — 서비스 자체 다운 → IT 관리자

## 1. 비밀번호 분실 (P0-2 미구현 — IT 관리자 우회)

### 1-1. 현재 시스템 상태

⚠️ **`/auth/password/reset` 미구현** (P0-2). 자가 reset 불가. IT 관리자 직접 reset 만 가능.

`services/auth-service/src/main/java/com/samhanair/logis/auth/web/AuthController.java` 검증 결과 — `/auth/login` + `/auth/register` (MASTER) + `/auth/me` 만 존재. `password` / `reset` / `change` 키워드 zero hit.

### 1-2. 우회 절차

1. **사용자**: 본인 부서장 (MANAGER) 또는 IT 관리자에게 비밀번호 reset 공식 요청
   - 신원 확인용 사번 + 본인 정보 (사진 주민번호 X — 부서장 대면 확인)
2. **IT 관리자**: 임시 비밀번호 발급 — 다음 두 방법 중 1개
   - 방법 A — `POST /auth/internal/accounts/{id}/disable` 후 신규 계정 발급 (audit 기록 보존)
   - 방법 B — 개발팀에 SQL 요청 (BCrypt 해시 직접 변경) :
     ```sql
     UPDATE auth.accounts
     SET password_hash = '$2a$10$...'  -- BCrypt 해시 (개발팀 생성)
     WHERE login_id = 'kimmiseon';
     ```
3. **사용자**: 임시 비밀번호로 로그인 → 부서장 대면 확인 후 사용

### 1-3. 정식 fix (Phase 11 진입 전 P0-2 권고)

P0-2 fix PR 1건으로 7개 누락 일괄 해소:
- 사용자 본인 비밀번호 변경 endpoint
- 첫 로그인 시 강제 변경 flag
- 이메일 reset link (notification-service 연계)
- MASTER 강제 reset endpoint
- 비밀번호 정책 (8자 / 특수문자)
- 5회 실패 시 잠금 + `failed_login_attempts` / `locked_at` 컬럼
- 비밀번호 변경 이력 (마지막 N개 재사용 금지)

## 2. 5회 실패 시 계정 잠금 (P0-2 미구현 안내)

### 2-1. 현재 상태

⚠️ **계정 잠금 미구현**. 무제한 시도 가능 — 보안 위협 (Phase 11 진입 전 P0-2 의무 fix).

증상:
- 비밀번호를 N번 잘못 입력해도 항상 같은 `401 Unauthorized` 응답
- "계정이 잠겼습니다" 메시지 절대 표시되지 않음
- IP rate limit 도 미구현 — 무한 brute-force 가능

### 2-2. 임시 가드 (운영팀 수동)

- 단톡방 / IT 관리자에게 의심스러운 시도 제보 즉시 IT 관리자가 해당 계정 disable (`POST /auth/internal/accounts/{id}/disable`)
- Phase 11 후 AWS WAF + RDS audit log 모니터링 (P0-8 백업 운영 PR 동반)

### 2-3. 운영자가 본인 계정 잠금이 의심되면

P0-2 미구현 시점에서는 **잠금 자체가 발생하지 않으므로**, "계정 잠금" 메시지가 보이면 다음 가능성:
- 본인 ROLE 이 `disabled` 처리됨 → IT 관리자에게 ROLE 활성 요청
- `accounts.deleted_at` 이 채워짐 (퇴사 처리) → MASTER 에게 복원 요청

## 3. 권한 부족 (403 Forbidden)

### 3-1. 증상

- 메뉴는 보이는데 클릭 시 빨강 토스트 "접근 권한이 없습니다"
- API 호출 시 HTTP 403 응답
- 본인은 SALES 인데 회계 endpoint 호출

### 3-2. 진단

[00-시작하기/03. 역할별 권한](../00-시작하기/03-역할별-권한.md) §3 service 표 대조.

| 본인 ROLE | 호출 endpoint | 결과 |
| --- | --- | --- |
| SALES | `POST /accounting/journals` | ❌ ACCOUNTANT 만 |
| WAREHOUSE | `POST /slips` | ❌ SALES 만 |
| ACCOUNTANT | `POST /slips/{id}/accept` | ❌ WAREHOUSE / INVENTORY 만 |
| MANAGER | (모든 endpoint) | ✅ |

### 3-3. 해결

1. 본인 ROLE 확인 — `GET /auth/me` 응답의 `role` 필드
2. 정상 ROLE 인데 거부되면 → 메모리 캐시 — 로그아웃 → 재로그인
3. 그래도 거부되면 → IT 관리자에게 ROLE 변경 요청 (MASTER 만 ROLE 변경 가능 — `PATCH /users/employees/{id}/role`)
4. ⚠️ P0-5 미구현 — desktop UI 부재. ROLE 변경은 IT 관리자가 backend API 또는 SQL 직접 수행

## 4. JWT 만료 / 401 Unauthorized

### 4-1. 증상

- 로그인 후 작업 중 갑자기 401 응답
- "다시 로그인하세요" 메시지
- 메뉴 클릭 시 로그인 화면으로 자동 이동

### 4-2. 원인

- JWT 만료 시간 = `app.security.jwt.access-token-ttl` (default 60분)
- refresh token 미구현 — 자동 갱신 X
- 다른 브라우저에서 같은 계정 로그인 → 기존 token 무효화 (single session 정책)

### 4-3. 해결

1. 로그인 화면에서 재로그인
2. 60분마다 한 번씩 발생 → 정상 — 작업 중 [저장] 자주 클릭
3. 잦은 401 → IT 관리자 / 개발팀에 JWT TTL 연장 요청 (Phase 11 후 refresh token P3 backlog)

## 5. 백엔드 500 / Eureka 비활성 (서비스 자체 다운)

### 5-1. 증상

- 모든 화면에서 빨강 토스트 "서버 오류 (500)"
- `Network Error` 또는 `Connection refused`
- 일부 메뉴만 작동 (Eureka 가 일부 service 만 발견)

### 5-2. 진단 (IT 관리자)

```bash
# Eureka 가 발견한 service 목록 확인
curl http://eureka.samhan-air.com/eureka/apps | grep instance

# 특정 service health
curl http://api.samhan-air.com/auth/actuator/health
```

응답 예시 (UP) — `{"status": "UP"}`. 응답 없음 또는 DOWN — service 다운.

### 5-3. 해결

1. **운영자**: 즉시 IT 관리자에게 보고 + 작업 임시 중단
2. **IT 관리자**:
   - 해당 service docker container 재시작 (`docker-compose restart auth-service`)
   - DB connection pool 확인 (PostgreSQL 다운 가능)
   - Eureka 재시작 시 모든 service 재등록까지 30초~2분 대기
3. 30분 이상 복구 안 됨 → 개발팀 escalation
4. Phase 11 후 EC2 Auto Recovery + Health Check Lambda 가 자동 재시작 (`project_phase11_aws.md`)

## 7. FAQ

**Q1. 비밀번호를 5번 잘못 입력했는데 계속 로그인이 됩니다.**
A. 정상 — 현재 P0-2 미구현으로 잠금 기능이 없습니다. Phase 11 진입 전 fix 예정. 보안상 정확히 입력 권장.

**Q2. 비밀번호 변경 메뉴가 어디 있나요?**
A. 미구현 (P0-2). IT 관리자에게 reset 요청 → 임시 비밀번호 발급 → 부서장 대면 확인.

**Q3. 다른 PC 에서 로그인하니 본 PC 에서 자동 로그아웃되었습니다.**
A. single session 정책 — 같은 계정의 새 로그인이 기존 token 을 무효화. 본 PC 에서 재로그인 필요. 동시 사용 필요 시 두 계정 발급.

**Q4. PARTNER 계정으로 desktop 에 로그인되지 않습니다.**
A. PARTNER 는 desktop 미접근 — `https://order.samhan-air.com` 거래처 PWA 만 사용 (partner-auth-service 별도 인증).

**Q5. DRIVER 계정으로 desktop 에 로그인되지 않습니다.**
A. DRIVER 는 desktop 미접근 — RN Expo 모바일 어플 (mobile-staff) 만 사용. SMS 받은 share token URL 만 접근.

**Q6. 로그인 후 빈 화면 / 메뉴가 안 보입니다.**
A. → [02. 화면 표시 안됨](02-화면-표시-안됨.md) 참조.

**Q7. "내 정보" 또는 "비밀번호 변경" 버튼이 안 보입니다.**
A. P1-2 미구현 — `/admin/users` / `/admin/profile` 라우트 부재. Phase 11 진입 전 P0-5 + P1-2 fix 권고.
