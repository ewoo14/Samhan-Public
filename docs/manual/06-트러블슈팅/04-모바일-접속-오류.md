## 1. 모바일 어플 종류

본 시스템의 모바일 어플은 2종 + WebView 1종:

| 종류 | 용도 | 사용자 | 기술 | 설치 |
| --- | --- | --- | --- | --- |
| **mobile-staff (RN Expo)** | 기사 어플 (배송 / 서명) | DRIVER | React Native + Expo | 사내 배포 |
| **영업 native 앱 (P1-4 미구현)** | 영업직원 견적 / 주문 | SALES | RN Expo (예정) | 미설치 |
| **WebView (slip share token)** | 거래처 서명 (외부) | 거래처 직원 | webview (mobile-staff 내부) | 어플 불필요 (URL) |

## 2. Expo 어플 시작 실패

### 2-1. 증상

- 어플 아이콘 탭 → splash 화면 잠깐 뜨고 종료
- 어플 진입 후 빈 화면 / 흰 화면 (10초 이상)
- "예기치 못한 오류" toast

### 2-2. 진단 + 해결

| 원인 | 해결 |
| --- | --- |
| 어플 cache 손상 | 핸드폰 설정 → 앱 → SamhanPublic Mobile → 저장공간 → 캐시 삭제 |
| 어플 데이터 손상 | 위와 같은 경로 → "데이터 삭제" → 어플 재시작 → 로그인 |
| OS 버전 미호환 | iOS 14 / Android 10 이상 필요. 미만 OS 는 IT 관리자 보고 |
| 어플 신버전 강제 업데이트 누락 | 사내 배포 페이지 (IT 관리자 안내) 에서 신버전 다운로드 |
| 인터넷 연결 부재 | Wi-Fi / LTE 확인 |
| 회사 VPN 필수 (P3 backlog) | 현재 미사용 |

### 2-3. 그래도 미해결

1. 어플 완전 삭제 → 사내 배포 페이지에서 재설치
2. IT 관리자에게 핸드폰 모델 + OS 버전 + 시간 보고
3. 임시 우회 — desktop 어플로 대체 작업 (영업직원 SALES 만 가능, DRIVER 는 모바일 외 우회 불가)

## 3. WebView 로딩 실패 (share token URL)

### 3-1. 증상

- DeliveryBatch SMS 의 link (`https://app.samhan-air.com/m/batch/abc123def456`) 클릭
- 빈 화면 / "잠시 후 다시 시도" toast
- 어플 자체는 정상인데 WebView 만 실패

### 3-2. 원인 + 해결

| 원인 | 해결 |
| --- | --- |
| share token 만료 (default 24시간) | 영업 / 창고에 [share token 재발행] 요청 → 새 SMS 수신 |
| share token 이미 사용됨 (서명 완료) | 정상 — 이미 처리된 배송, 추가 작업 불필요 |
| 잘못된 token (오타 / SMS 잘림) | 영업 / 창고에 SMS 재발송 요청 |
| 회사 도메인 차단 (이동통신사 콘텐츠 필터) | 다른 회선으로 시도 / 데이터 켜기 |
| WebView cookies 비활성 | 핸드폰 브라우저 설정 → 쿠키 허용 |
| HTTPS 인증서 오류 (Phase 11 cutover 전) | IT 관리자에게 보고 — 인증서 갱신 |

### 3-3. 거래처 직원 (외부 사용자) 시나리오

거래처 직원이 SMS 링크 클릭 → WebView 로딩 → 본인 서명 + 기사 서명 → 자동 슬립 DELIVERED 전이.

거래처 측 문제 시:
- 본 시스템 어플 설치 X — WebView 만 사용
- 거래처 핸드폰의 SMS 차단 / 스팸 처리 → 전화로 안내
- 거래처 측 인터넷 부재 → 기사가 본인 폰으로 거래처 직원 서명 받기 (대리)

## 4. GPS 권한 거부

### 4-1. 증상

- 어플 진입 시 "위치 권한 필요" 알림 → 거부 클릭
- 위치 보고 미작동 → 어플 우상단 "GPS 끔" 표시
- backend log "DriverLocation 보고 0건"

### 4-2. 원인 + 해결

| 원인 | 해결 |
| --- | --- |
| 사용자가 권한 거부 | 핸드폰 설정 → 앱 → SamhanPublic Mobile → 권한 → 위치 → "항상 허용" |
| OS 자체 위치 서비스 OFF | 설정 → 위치 → ON |
| 백그라운드 위치 권한 거부 (Android 10+) | "항상 허용" 필수 (앱 종료 시에도 GPS 보고) |
| 배터리 절약 모드 | 절약 모드 OFF + 본 어플 "최적화 제외" 설정 |
| iOS 정확한 위치 OFF | 설정 → 개인정보 보호 → 위치 → 본 어플 → "정확한 위치" ON |

### 4-3. GPS 권한 없이 운영 가능?

**불가** — driver 위치 보고는 본 시스템의 핵심 audit:
- 거래처 도착 시각 자동 기록
- 배송 경로 추적 (P3 backlog)
- 문제 발생 시 책임 소재 확인

GPS 거부 driver 는 INTERNAL 자격 박탈 가능성 (운영팀 결정).

## 5. 카메라 권한 거부 (서명 / 사진)

### 5-1. 증상

- [전자 서명] 화면 진입 시 "카메라 권한 필요" → 거부 클릭
- 거래처 도착 사진 [첨부] 클릭 시 권한 거부

### 5-2. 해결

핸드폰 설정 → 앱 → SamhanPublic Mobile → 권한 → 카메라 + 갤러리 → "허용".

### 5-3. 우회 (권한 거부 시)

- 서명 = signature pad 위에 손가락 그리기 (카메라 불필요) — 카메라는 서명 후 미러링 캡처용 (선택)
- 사진 첨부 = P3 backlog (`04-모바일/04-사진-첨부.md` 미구현 안내) — 현재 미사용

## 6. 푸시 알림 미수신

### 6-1. 증상

- 신규 배차 매칭 push 알림이 안 옴
- arologis 자동 매칭 후 어플에 알림 부재

### 6-2. 원인 + 해결

| 원인 | 해결 |
| --- | --- |
| 사용자가 push 권한 거부 | 핸드폰 설정 → 앱 → 권한 → 알림 → 허용 |
| 어플 종료 (force-quit) 상태 | iOS — 백그라운드 종료 시 알림 미수신. 어플 항상 살림 권장 |
| `appUserId` null (DriverSeeder skeleton) | 개발팀 — Driver.appUserId 가 auth 의 user.id 와 매핑되어야 함 |
| EXTERNAL driver (INSUNG / KAKAO) | 정상 — 본 어플 알림 채널 없음. 인성 자체 채널 / 카톡 사용 |
| NotificationClient 비활성 (P1-1 — Aligo / FCM 미통합) | IT 관리자 / 개발팀 |
| FCM token 만료 (장기 미접속) | 어플 재시작 → token 갱신 |

### 6-3. 임시 우회 — 본인이 직접 list 조회

어플 진입 → [오늘의 배송] (`GET /driver-app/arologis/dispatches/today`) 수동 새로고침.

## 7. share token 만료 / 403

### 7-1. 증상

- DeliveryBatch SMS 의 URL 클릭 시 "권한 없음" 또는 403
- 또는 빈 화면 + "token expired" toast

### 7-2. 원인 + 해결

| 원인 | 해결 |
| --- | --- |
| token 만료 (default 24시간) | 영업 / 창고에 share token 재발행 요청 (`POST /delivery-batches/{id}/regenerate-token`) |
| token 이미 사용됨 (slip DELIVERED) | 정상 — 작업 완료, 재서명 불필요 |
| token 변조 / 오타 | SMS 원본 재발송 |
| 슬립이 cancelled / rejected | 영업 / 창고에 슬립 상태 확인 → 신규 슬립 요청 |
| Gateway / share token endpoint 다운 | IT 관리자 |

## 8. 어플 자체가 미설치 (P1-4 — 영업 native 앱)

### 8-1. 증상

- 영업직원이 [영업 모바일 앱] 다운로드 시도 → 어플 부재
- 사내 배포 페이지에 영업 어플 없음

### 8-2. 원인

P1-4 미구현 — 영업직원 견적 / 주문 native 앱이 아직 개발되지 않음.

### 8-3. 우회 (현재 운영)

- 영업직원이 desktop 어플로 견적 / 주문 처리
- 외부 출장 시 = legacy v4 webview (`https://order.samhan-air.com`) 임시 사용

## 9. FAQ

**Q1. 어플 신버전이 자동 업데이트 안됩니다.**
A. Expo OTA 자동 업데이트 — 어플 진입 시 자동 다운로드 (네트워크 필수). 미작동 시 사내 배포 페이지에서 수동 재설치.

**Q2. iOS / Android 둘 다 지원하나요?**
A. 네 — RN Expo 가 두 OS 모두 빌드. iOS 14+ / Android 10+ 권장.

**Q3. Wi-Fi 만 사용해도 되나요?**
A. 권장 X — 배송 중 Wi-Fi 부재 시 GPS 보고 / 서명 송신 실패. LTE / 5G 권장.

**Q4. 어플 데이터 사용량이 많습니다.**
A. GPS 보고 = 60초마다 1건, 서명 1건 = 약 50KB. 일평균 약 20MB 예상. 회사 데이터 plan 사용 권장.

**Q5. 핸드폰을 분실했습니다.**
A. 즉시 IT 관리자에게 보고 — 본인 계정 disable + 새 핸드폰 재로그인.

**Q6. 다른 사람의 핸드폰으로 본인 계정 로그인 가능?**
A. 가능 — single session 정책으로 기존 token 무효화. 본인 핸드폰 복구 시 재로그인.

**Q7. WebView 의 서명이 저장 안됩니다.**
A. 네트워크 / share token 만료 가능성. 영업 / 창고에 재발행 요청.

**Q8. 어플 종료 후에도 GPS 가 보고됩니까?**
A. Android 10+ 는 "항상 허용" 권한 + 배터리 최적화 제외 시 가능. iOS 는 백그라운드 위치 (UIBackgroundModes location) — 어플 종료 시 미작동.

**Q9. 핸드폰 배터리가 빨리 닳습니다.**
A. GPS 백그라운드 보고 영향 — 정상. 보조 배터리 권장 (모든 driver 에 회사 지급 권장).

**Q10. 거래처가 서명 거부합니다.**
A. SMS 의 share token URL 을 거래처 직원이 본인 폰으로 직접 접속 → 서명 받기. 거부 시 기사가 사진 + 본인 서명만 등록 → MANAGER 결재 (P3 — 향후 정식 거부 처리 도입).
