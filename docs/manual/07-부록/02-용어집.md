## 1. 슬립 (전표) 도메인

| 용어 | 풀네임 | 정의 |
| --- | --- | --- |
| **슬립 (Slip)** | 전표 | 거래의 단위 — 영업이 발행, 창고가 처리, 회계가 정산. 11 status workflow. |
| **슬립번호** | slipNumber | 사용자 노출 식별자. `S-2026-NNNNN` 형식 (UUID 비공개 가드). |
| **헤더 (Header)** | 슬립 헤더 | 슬립 1건의 메타 (거래처 / 발행일 / 합계 등). 1건. |
| **라인 (Line)** | 슬립 라인 | 슬립 내 제품 단위. 다수. 제품 / 수량 / 단가 / 라인합계. |
| **OUTBOUND 슬립** | 출고 슬립 | 창고 → 거래처. 매출 발생 (회계 분개). |
| **INBOUND 슬립** | 입고 슬립 | 공급사 → 창고. 재고 증가. |
| **TRANSFER 슬립** | 이동 슬립 | 창고 ↔ 창고 (재고 이동). 매출 X. |
| **DRAFT** | 임시저장 | 영업이 작성 중. 발송 전. |
| **SAVED** | 저장 | 영업이 저장 확정. 발송 대기. |
| **SENT** | 발송 | 영업이 창고로 전달. 창고 list 진입. |
| **ACCEPTED** | 접수 | 창고가 슬립 접수. 재고 reserve. |
| **PROCESSING** | 처리 | 창고가 picking 중. |
| **INSPECTING** | 검수 | 창고가 picking 완료, 검수 중. |
| **COMPLETED** | 완료 | 창고가 검수 완료. 재고 deduct (실차감). |
| **SHIPPING** | 출하 | 트럭 적재 완료. 기사 출발. |
| **DELIVERED** | 배송 완료 | 기사가 거래처 도착, 모바일 서명 수신. |
| **CONFIRMED** | 정산 | 회계가 정산. 자동 분개 생성. ★ |
| **CANCELLED** | 취소 | DRAFT/SAVED/SENT 단계만 가능 — 영업 취소. |
| **REJECTED** | 거절 | MANAGER 가 임의 단계에서 거절. 사유 필수. |
| **idempotency-key** | 멱등 키 | 중복 요청 차단. UUID 헤더 (`Idempotency-Key`). |

## 2. 거래처 도메인

| 용어 | 풀네임 | 정의 |
| --- | --- | --- |
| **거래처 (Partner)** | 매출처 / 매입처 | 슬립의 상대방. 사업자번호 + 신용 한도 보유. |
| **partnerCode** | 거래처 코드 | 사용자 노출 식별자. `P-2026-NNNN` 형식. |
| **사업자번호** | 사업자등록번호 | 한국 국세청 표준 10자리. 거래처 unique. |
| **여신** | 신용 한도 | 거래처별 매출 가능 금액 상한. |
| **단가그룹** | 영업단가그룹 | 거래처별 적용 단가표 (기본 / 할인 / VIP). |
| **결재자** | 거래처 결재자 | 거래처 측 PARTNER_ADMIN ROLE. PARTNER 의 상위. |
| **거래처 주문** | PartnerOrder | 거래처가 PWA / 모바일에서 발주. draft → confirm → slip 자동 발행. |
| **partner-auth** | 거래처 인증 | 별도 인증 service (`partner-auth-service`). 본 직원 auth-service 와 분리. |
| **신용 history** | 거래처 신용 이력 | 거래처별 매출 / 미수금 / 결제 이력 시계열. |
| **첨부파일** | partner attachment | 거래처 등록 시 사업자등록증 등 multipart upload (P0-3 — MinIO). |

## 3. 재고 / 창고 도메인

| 용어 | 풀네임 | 정의 |
| --- | --- | --- |
| **재고 (Inventory)** | 재고 | 창고 × 제품 단위 잔량. balance / reserved / available. |
| **balance** | 총재고 | 창고에 있는 전체 수량. |
| **reserved** | 예약재고 | 슬립이 reserve 한 수량 (출고 대기). |
| **available** | 가용재고 | balance - reserved. 신규 출고 가능 수량. |
| **lot** | 로트 | 입고 단위. FIFO 차감 (V5 migration). |
| **창고코드** | warehouseCode | `HQ-001` (본사) / `VH-001` (가산지점) 등. |
| **transfer** | 창고이동 | 창고 ↔ 창고 재고 이동. 8 status workflow. |
| **deduct** | 차감 | 재고 실 차감. slip COMPLETED 시점. |
| **reserve** | 예약 | 재고 가예약. slip ACCEPTED 시점. release = 예약 해제. |
| **balance / movements / lots** | 재고 조회 endpoint | `/balances`, `/movements`, `/lots`. |
| **검수 (Inspect)** | 입고 검수 / 출고 검수 | 입고 시 수량 / 품질 확인 (P0-9 미구현 — Stage 2 신규). |
| **재고 실사** | cycle count | 정기 실물 vs 시스템 일치 검증 (P2-6 미구현). |
| **DeliveryBatch** | 배송 묶음 | 같은 기사에게 여러 슬립 묶어 SMS 1건 발송. |
| **shareToken** | 공유 토큰 | DeliveryBatch 의 외부 접근 token. 24시간 만료. |

## 5. 배차 / arologis 도메인

| 용어 | 풀네임 | 정의 |
| --- | --- | --- |
| **arologis** | 아로로지스 | Phase 10 신규 service. 카카오톡 배차 자동 파싱 + 기사 매칭. |
| **Dispatch** | 배차 | 1일 단위 배차 묶음. 도착일 + 유형 + 차량 N개. |
| **DispatchType** | 배차 유형 | DAY (주간) / NIGHT (야상) / EXPRESS (특급). |
| **Vehicle** | 차량 | dispatch 내 차량 1대. tonnage + label + 기사 1명. |
| **VehicleStop** | 정차 | vehicle 내 정차 1건. 주소 + 거래처 + 슬립번호. |
| **StopStatus** | 정차 상태 | UNPARSED / PENDING / DISPATCHED / EN_ROUTE / ARRIVED / COMPLETED / FAILED. |
| **VehicleTonnage** | 톤수 | TONNAGE_1 / TONNAGE_1_4 / TONNAGE_2_5 / TONNAGE_5. |
| **Driver** | 기사 | 배송기사. 5종 source 분류. |
| **driverCode** | 기사 코드 | `DRV-2026-NNN` 형식. |
| **DriverSource** | 기사 소스 | INTERNAL / EXTERNAL_INSUNG_QUICK / EXTERNAL_KAKAO / EXTERNAL_SMS / MANUAL. |
| **DriverMatcher** | 기사 매처 | 자동 매칭 알고리즘. Mock / InsungQuick / (장기 KakaoBot). |
| **MatchSource** | 매칭 소스 | AUTO_MOCK / AUTO_INSUNG / MANUAL / KAKAO_FALLBACK. |
| **KakaoDispatchParser** | 카톡 배차 파서 | 카톡 메시지 → ParsedDispatch 변환. 80% 정확도. |
| **SlipResolver** | 슬립 매핑 | parsedPartnerCode → slipId 매핑 (W10-4). |
| **slipBridged** | 슬립 양쪽 저장 | 서명 등록 시 slip-service 양쪽 저장 성공 여부. |

## 7. 시스템 / 기술 도메인

| 용어 | 풀네임 | 정의 |
| --- | --- | --- |
| **MSA** | 마이크로서비스 아키텍처 | 본 시스템 = 14 service. service-per-DB. |
| **Eureka** | Eureka Server | service discovery. 8761 port. |
| **Gateway** | API Gateway | 모든 외부 요청의 단일 진입점. 인증 + routing. |
| **service-per-DB** | service 별 DB | 각 service 가 독립된 PostgreSQL DB. CQRS. |
| **BaseEntity** | 기본 엔티티 | 7 audit 필드 (`id`, `createdAt`, `createdBy`, `updatedAt`, `updatedBy`, `deletedAt`, `deletedBy`) 의무. |
| **Soft Delete** | 소프트 삭제 | `deleted_at` 채움 + row 보존. 복원 가능. |
| **JWT** | JSON Web Token | 인증 token. 60분 default 만료. |
| **X-User-* 헤더** | 사용자 헤더 | Gateway 가 주입. user-id / role / partner-id. |
| **X-Internal-Token** | 내부 토큰 | service 간 호출 인증. INTEGRATION ROLE 가상 부여. |
| **Idempotency-Key** | 멱등 키 헤더 | 중복 요청 차단 (확정 endpoint). |
| **PostgreSQL** | PostgreSQL | DB. 한국 회계 audit 보존 검증. |
| **Spring Boot 3** | Spring Boot 3.x | backend 프레임워크. Java 17. |
| **Gradle** | Gradle | 빌드 도구. multi-project (`gradle settings`). |
| **Electron** | Electron | desktop 어플 frame. dist/ build. |
| **Vite** | Vite | desktop dev / build tool. HMR. |
| **EJS** | Embedded JavaScript | 견적서 server-side rendering (옵션 B2). |
| **MinIO** | MinIO | 첨부파일 object storage (S3 호환). P0-3. |
| **Aligo** | 알리고 SMS | SMS gateway (P1-1 미통합). |

## 8. ROLE / 권한 도메인

| 용어 | 풀네임 | 정의 |
| --- | --- | --- |
| **MASTER** | 시스템 관리자 | 김미선 대표. 전 service 전 endpoint. |
| **MANAGER** | 부서장 | 영업총괄 / 창고소장 / 회계과장. 결재 / 거절. |
| **SALES** | 영업직원 | 거래처 등록 / 슬립 발행 / 견적 / 주문. |
| **WAREHOUSE** | 창고작업자 | 출고 패킹 / 입고 검수 (작업 단계). |
| **INVENTORY** | 재고관리자 | 재고 이동 / 조정. |
| **ACCOUNTANT** | 회계담당 | 분개 입력 / 슬립 정산 / 보고서. |
| **PARTNER** | 외부 거래처 | 주문서 작성 / 본인 history. desktop 미접근. |
| **DRIVER** | 배송기사 | 모바일 서명 / GPS 보고. desktop 미접근. |
| **DEVELOPER** | 개발팀 | read-only + 일부 master data. |
| **INTEGRATION** | 시스템 가상 ROLE | service 간 호출. 사용자 부여 불가. |
| **PARTNER_ADMIN** | 거래처 결재자 | PARTNER 의 상위. 거래처 측 결재. |
| **button-level RBAC** | 버튼 단위 권한 제어 | UI 버튼 표시 / 비표시 + backend `@PreAuthorize` 이중 가드. |
