### 1-2. 한국 국세청 표준 양식

| | 상호 | 회사 상호 |
| | 대표자 | 회사 대표자 |
| | 사업장 주소 | 회사 주소 |
| | 업태 / 종목 | 회사 업태 / 종목 |
| **공급받는자** | 등록번호 | 거래처 사업자등록번호 (`Partner.businessNumber`) |
| | 상호 | 거래처 상호 |

| | 사업장 주소 | 거래처 주소 |

## 2. 현 시점 임시 대응

> 본 절은 **P0-4 fix PR 머지 전** 까지 한정 적용되는 임시 절차입니다.

### 2-1. 수기 세금계산서 발행 (가장 단순)

소량 발행 시 권장:

1. 본 시스템 [01-영업/03. 슬립 발행](../01-영업/03-슬립-발행.md) 으로 슬립 CONFIRMED 완료
2. 슬립 상세 화면에서 거래처 정보 / 라인 / 합계를 확인
3. **종이 세금계산서 양식** (한국 국세청 표준 양식) 에 수기 작성
   - 양식: 문구점 / 인쇄소에서 구매 가능 (전자세금계산서 의무화 이전 양식)
   - 또는 [국세청 양식 자료실](https://www.nts.go.kr/) 다운로드 후 자체 인쇄
4. 회사 인감 날인 후 거래처에 우편 / 직접 전달
5. 사본 1부 보관 (회계 audit 의무)

> ⚠️ **전자세금계산서 의무 발행 대상 주의** — 한국은 직전 연도 공급가액 합계가 일정 기준 (3억 이상) 초과 시 전자세금계산서 발행 의무. 수기 발행은 **기준 미만 사업자만** 가능. 의무 대상은 §2-2 또는 §2-3 사용.

### 2-2. 외부 ERP 활용 (전자세금계산서)

이카운트 / 더존 SmartA / 세무사 사무실 ERP 사용 시:

1. 본 시스템 슬립 CONFIRMED 완료
2. 슬립 정보를 외부 ERP 에 수동 입력 (거래처 / 품목 / 금액)
3. 외부 ERP 의 전자세금계산서 발행 기능 사용
4. 발행 결과 (일련번호 / 발행일자) 를 본 시스템 분개 적요에 기록

> ⚠️ **이중 입력 위험** — 본 시스템과 외부 ERP 양쪽에 거래처 / 슬립 / 분개가 존재. P0-4 fix 후 단일화 필수.

### 2-3. 국세청 Hometax 직접 발행 (개별)

소량 발행 시 무료 (별도 ERP 불필요):

1. [홈택스](https://www.hometax.go.kr) 로그인 (공인인증서 / 간편인증)
2. **세금계산서/계산서/영수증** → **세금계산서 발급**
3. 본 시스템 슬립 정보를 화면에 수동 입력
   - 공급받는자 사업자등록번호 / 상호
   - 품목 / 수량 / 단가 / 공급가액 / 세액
4. 발급 → 거래처에 자동 email 발송
5. 발급 일련번호를 본 시스템 분개 적요에 기록

### 2-4. 부가세 신고 임시 대응

월별 / 분기별 부가세 신고 (1월 / 4월 / 7월 / 10월):

1. 본 시스템 [02. 보고서](02-보고서.md) §2 시산표에서 `220 부가세예수금` / 매입 부가세 (해당 시) 잔액 확인
2. Hometax 부가세 신고서에 수기 입력
3. 매출처별세금계산서 합계표 / 매입처별세금계산서 합계표 첨부 (Hometax 자동 생성 또는 외부 ERP)

## 3. 우회 절차 체크리스트

월말 회계 마감 시 본 시스템 + 외부 발행 정합 체크:

| 항목 | 확인 방법 |
| --- | --- |
| 슬립 CONFIRMED 건수 == 외부 발행 건수 | 본 시스템 슬립 목록 (status=CONFIRMED) vs 외부 ERP / Hometax 목록 |
| 슬립 합계 == 외부 발행 합계 | 시산표 401 상품매출 vs 외부 매출 합계 |
| 부가세 합계 일치 | 시산표 220 부가세예수금 vs 외부 부가세 합계 |
| 거래처별 매출 일치 | 거래처별 슬립 합계 vs 외부 거래처별 발행 합계 |

> 불일치 발견 시 회계담당자 즉시 확인. P0-4 fix 후에는 본 시스템 단독으로 충분.

| 외부 ERP 와 본 시스템 매출 합계 mismatch | 슬립 status / 분개 시점 차이 | 시산표 401 상품매출 vs 외부 매출장 매월 비교 |

| 부가세 신고서 자동 생성 필요 | 미구현 (P0-1 §3 14건 중 부가세신고 포함) | §2-4 임시 대응 |
| `해당 ROLE 권한 없음` | ACCOUNTANT 외 ROLE | MASTER 에게 ROLE 추가 요청 |

## 5-1. 수정 이력 보기 (Phase 12 step-4c, PR-H4c FE rollout)

> **PR-H4c 변경** — P0-4 fix 후 정식 TaxInvoicePage 도입 시 본 절의 audit overlay 가 자동 적용됩니다. 본 절은 P0-4 fix 후 사용자 동작 안내 (시드 패턴 PR-H2 `02-출고-처리.md` § 2-9 1:1 복제 — 도메인 라벨만 교체).

### 5-1-1. 세금계산서 헤더 "수정 N회" badge

TaxInvoicePage 우측 상단에 **수정 N회** badge 표시. 임계 색상 (0/1~4/5~9/10+) PR-H2 시드와 동일.

### 5-1-2. 필드별 audit overlay (공급자/공급받는자/품목/금액)

각 필드 우측에 가장 최근 변경이 inline 으로 표시:

```
공급받는자 상호    삼한전자(주)        ~~삼한전자~~        ● 이회계 13:32
공급가액          1,500,000            ~~1,200,000~~        ● 이회계 13:31
부가세            150,000              ~~120,000~~          ● 이회계 13:31
합계              1,650,000            ~~1,320,000~~        ● 이회계 13:31
품목 라인         삼한 노트북 어댑터   (시드 그대로)
```

### 5-1-3. NTS Hometax 전송 후 잠금

전자세금계산서가 NTS Hometax 에 전송된 직후부터는 직접 수정 불가:

```
[잠금 banner]
이 세금계산서는 NTS 에 전송되었습니다 — 수정세금계산서 발급으로만 정정 가능합니다.
한국 세법 보존 의무 (전송 후 수정세금계산서 별도 절차).

[수정세금계산서 발급]  ← 클릭 시 신규 세금계산서 화면 (반대 부호)
```

### 5-1-4. 분개와 audit 연계 (자동 분개)

세금계산서 발행 시 자동 트리거되는 분개 (110/401/220) 의 audit 도 함께 누적되어, [01. 분개 입력](01-분개-입력.md) § 6-1 의 JournalDetailPage 에서 동일 actorName + 색상 hash 로 일관 표시.

### 5-1-5. UUID 비공개 가드

화면 어디에도 UUID 노출 0건. 비즈니스 식별자만 표시:

- 세금계산서 일련번호 (NTS 발급 후) / 거래처 사업자등록번호 (123-45-67890) / 한국 계정 코드 (100100 등)
- actorName 풀네임 + 색상 dot

### 5-1-6. 1초 SSE 실시간 sync

ACCOUNTANT 가 세금계산서를 수정하면 동시에 화면을 보고 있던 MANAGER / MASTER 의 TaxInvoicePage 가 1초 안에 자동 갱신.

```
[우측 상단 toast]
실시간 변경 감지 — 0.8초
이회계 님이 공급가액 을 "1,500,000" 으로 수정했습니다. (rev #2)
```

> 본 절은 P0-4 fix PR 머지 후 정식 TaxInvoicePage 도입 시 자동 적용. 본 PR-H4c FE rollout 으로 사전 가이드만 시드.
