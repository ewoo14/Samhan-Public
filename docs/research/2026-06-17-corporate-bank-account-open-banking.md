## 2. 오픈뱅킹 비용 — 비교데이터 (핵심)

### 2.1 비용 모델

```
월 변동비 = 계좌수 × (월 폴링횟수/계좌) × 호출단가
  · 폴링 1회 = 계좌당 거래내역조회 1호출 (신규 거래 ≤25건 가정; 초과 시 +페이지)
  · 호출단가 = 견적 미확정. 보수적 30원 / 인하 반영 10원 / 최저 보도치 3원 의 3개 시나리오
  · 잔액조회를 함께 폴링하면 호출수 약 2배
+ 고정비(별도, 비공개): 월 기본료·최소이용료 + 자격 취득 일회성(보안점검 등)
```

### 2.5 해석

- **폴링 간격이 1순위 비용 레버**: 1분 ↔ 10분 = **정확히 10배**. 10분 ↔ 60분 = 6배.

### 2.6 온디맨드(조회 버튼) — **최저비용 + 권장 모델**

주기 폴링 대신 **사용자가 입금매칭 화면에서 "조회" 버튼을 누를 때만** 호출하면, 유휴 폴링 낭비(§3-2)가 0이 되어 비용이 **실제 매칭 활동량**에만 비례한다. (조회 1회 = 선택 계좌 수만큼 호출.)

```
월 호출수 = 일 조회횟수 × 계좌수 × 22영업일
```

| 일 조회횟수 | 계좌 | 월 호출 | @3원 | @10원 | @30원 |
|---|---|---:|---:|---:|---:|
| 10회 | 5 | 1,100 | 3,300 | 11,000 | 33,000 |
| 20회 | 5 | 2,200 | 6,600 | 22,000 | 66,000 |
| 50회 | 5 | 5,500 | 16,500 | 55,000 | 165,000 |
| 10회 | 10 | 2,200 | 6,600 | 22,000 | 66,000 |
| 20회 | 10 | 4,400 | 13,200 | 44,000 | 132,000 |
| 50회 | 10 | 11,000 | 33,000 | 110,000 | 330,000 |

**비교**: 5계좌 기준, 온디맨드 20회/일(2,200호출) = **10분 폴링(5,940호출)의 ~37%**, 1분 폴링(59,400호출)의 **~4%**. 활동량이 적으면 더 낮아진다.

**장점**: ① 유휴 호출 0 → 최저비용 ② 연속 폴링이 아니라 rate-limit 위험↓ ③ 스케줄러 인프라 불요 ④ **회계 실무 워크플로우와 자연 일치**(직원이 입금 확인할 때 조회 → 매칭). **단점**: 실시간 아님(누군가 눌러야 갱신) — 그러나 거래원장 반영은 본래 사람이 검토·확정하는 작업이라 무관.

**🚩 이미 이 모델로 구현됨**: SP-09-4 `DepositMatchController POST /fetch-and-match` + `DepositMatchPage` 의 조회 버튼 = **온디맨드**(스케줄러 아님). 즉 가장 저렴한 방식이 이미 스캐폴드돼 있다.

**추가 절감**: ① 입금 예상 계좌만 선택 조회 ② 동일 기간 N분 내 재조회 캐시/디둡 ③ last-fetched 이후 분(分)만 조회(페이지 수 축소).

### 2.7 호출 단가 결정 구조 + 초기 자격·보안 비용 (고정비)

**호출 단가는 어떻게 정해지나** — 공개 정가표 없음. 금융결제원(KFTC)이 운영, 이용기관이 KFTC 와 계약 시 다음으로 확정:
- **API 종류별 차등**: 잔액조회 < 거래내역조회 < 출금이체 (조회가 가장 쌈)
- **이용기관 유형·등급**: 핀테크/전자금융업자 vs 일반기업 자사용 — 분담금·이용료 체계 상이
- **거래량 협상**: 대량 이용 시 감면(펌뱅킹 관행 동일) + 계좌 보유 은행 정산 수수료 포함
- **추세**: 출범(2019) 펌뱅킹 대비 1/2~1/5 → 이후 추가 인하 → 조회 **약 3~30원대(보도치)**. → §2 표를 3/10/30원 범위로 둔 이유. **정확치 = KFTC/주거래은행 견적 필수**.

**초기 자격·보안 비용 (고정비)** — 직접 이용기관 경로:
- **절차**: 적합성 심사 → 개발·시험 → **금융보안원(FSI) 보안점검** → 이용계약 (수개월)
- **비용 구성**: ① 금융보안원 보안점검 수수료(점검 규모별, 비공개·수백만원대 추정) ② 보안 인프라/솔루션 — 전송암호화(TLS)·키관리(HSM/KMS)·접근통제·로그/감사·취약점점검(모의해킹)·(요건 시)망분리, **기존 인프라 수준에 따라 천차만별** ③ 연 1회 정기 점검(유지비)
- **🔑 핵심 트레이드오프**: 이 초기·유지 보안비용을 **회피하려고 ASP(CODEF/뱅크다)를 씀** — ASP 가 자격·보안점검 대신 부담 → 초기비용 ~0, 대신 호출단가/월정액↑. **"거래량 × 기존 보안인프라 수준"이 직접 vs ASP 손익분기**를 가름(저물량·보안인프라 부족 → ASP / 고물량·금융권 보안 기보유 → 직접).
- 정확 수수료·통과기준·기간 = 비공개 → **금융보안원·KFTC·주거래은행 견적**(딥리서치 미확정, §7).

## 3. ⚠️ 비용 외 두 가지 벽 (고빈도 폴링)

1. **조회 한도(rate limit)** — 오픈뱅킹에 일/월 조회 한도가 있을 수 있고, 1분·24h 폴링(계좌당 43,200회/월, 1,440회/일)은 한도에 걸릴 위험. 딥리서치도 "고빈도 다계좌 폴링에 한도가 충분한지"를 **미확정**으로 남김.
2. **과잉 폴링 낭비** — 오픈뱅킹은 push 없음 → 입금이 없어도 매 주기 호출 → 대부분 "신규 0건" 응답에 과금. 입금이 시간당 수 건 수준이면 **1분 폴링의 실익이 거의 없음**. 진짜 실시간 push 가 필요하면 **펌뱅킹 입출금통보**(건당 수백원, push)와 비교 필요.

## 4. 거래처명 매칭 한계 (요구사항의 핵심)

- 오픈뱅킹·CODEF **모두 정규화된 상대방(거래처)명 필드를 주지 않음**. 제공되는 건 **적요(`printed_content`)** 텍스트뿐.
- 따라서 "입금내역에 거래처명 등록 → 거래원장 자동반영"은 **적요 파싱 + 자체 거래처 마스터 매핑** 로직이 별도로 필요.
- 정확도 난점: 동명이인·약칭·`(주)` 유무·법인명 변형 → **퍼지 매칭** 또는 사용자 확인 UI 필요. (사업자번호·예금주명 등 보조키를 어느 채널이 주는지 추가 확인 필요.)

## 5-A. 확장 시나리오 — 법인카드 동시 연동 (카드 10 + 계좌 12)

**핵심: 오픈뱅킹 API 모듈은 카드 미지원**(은행 계좌 전용: 잔액/거래내역). **단, 같은 금융결제원 포털의 별도 서비스 "어카운트인포"는 카드 포함**("내카드 한눈에") — 2026-06-17 개발책임자 지적으로 정정.
- ⚠️ **그러나 "무엇을 주느냐"가 관건**: 어카운트인포는 "숨은 금융자산(계좌·카드·보험) 한 번에 조회 + 비활동성계좌 해지·잔고이전"의 **자산 발견/정리 성격(소비자=국민 대상)**. "내카드 한눈에"는 통상 **보유 카드 + 결제예정(청구)금액 + 포인트** 수준. 거래원장에 필요한 **카드 승인내역 라인아이템(가맹점·금액·일시)** 까지 주는지는 **별개 — 확인 필요**.
- **확정해야 할 2가지**: ① "내카드 한눈에" API 응답이 **승인내역 라인아이템** vs 보유/결제예정총액 중 무엇인가 ② **법인/이용기관(B2B) 사용 가능** 여부(어카운트인포는 개인 본인 자산조회 취지).
- **분기**: ①이 승인내역을 주면 → **금융결제원 단일 포털로 계좌(오픈뱅킹)+카드(어카운트인포) 모두 공식 채널** 가능(CODEF 스크래핑보다 안정·우월). 보유/청구총액만이면 → 카드 승인내역은 여전히 **카드사 직접/CODEF/여신금융협회** 필요.
- **✅ 검증(2026-06-17 웹확인)**: 어카운트인포 카드 API 실재 — `카드목록조회`/`카드기본정보조회`/`카드청구기본정보조회`/**`카드청구상세정보조회`**(청구 라인아이템 가능성). **그러나 포털 명시 이용대상 = "만 19세 이상 내국인"(개인)** + 취지 "국민 누구나 자신의 숨은 금융자산 조회" → **법인카드/법인계좌 자동화엔 부적합 추정**. 또 '청구(billing)' 기반이라 실시간 승인내역과 **월 청구주기 시차** 가능. ⇒ **법인카드는 여전히 카드사 직접/CODEF/여신금융협회 필요**(이유 정정: '포털에 카드 없음' ❌ → '어카운트인포 카드는 개인용' ⭕). 법인 지원·필드 최종확인 = 개발자포털 로그인/문의.
- 출처: [openapi.kftc.or.kr](https://openapi.kftc.or.kr/), [어카운트인포 서비스](https://openapi.kftc.or.kr/service/accountInfo), [오픈API 현황](https://openapi.kftc.or.kr/main), [developers.kftc.or.kr](https://developers.kftc.or.kr/dev).

**채널 선택지**
- **(A) 통합 — CODEF 단일**: 계좌 12 + 카드 10 = 22소스 모두 CODEF 한 채널. 연동 1개, 오픈뱅킹 자격·보안점검 부담 0. 단 스크래핑 안정성↓ + CODEF 단가(비공개). **카드가 끼면 어차피 CODEF 필요 → 통합 매력↑.**
- **(B) 하이브리드**: 계좌=오픈뱅킹(저렴·안정, 단 자격/보안), 카드=CODEF. 연동 2개·장애대응 2배. 계좌 물량 크고 장기 운영이면 유리.

**호출량·비용 (온디맨드, 22소스; 조회 1회 = 소스 수만큼 호출)**

| 일 조회 | 월 호출(계좌+카드) | 계좌측(오픈뱅킹 @3~30원) | 카드측(CODEF, 견적) |
|---|---:|---:|---|
| 10회 | 4,840 (2,640+2,200) | 7,920~79,200원 | 2,200호출 × CODEF단가 |
| 20회 | 9,680 (5,280+4,400) | 15,840~158,400원 | 4,400호출 × CODEF단가 |
| 50회 | 24,200 (13,200+11,000) | 39,600~396,000원 | 11,000호출 × CODEF단가 |

> 카드 승인내역은 입금만큼 즉시성이 불필요 → **일 1~2회/마감 시 조회로 충분**한 경우가 많아 카드 호출은 더 낮게 잡아도 됨. 계좌측 단가는 범위 명확, **카드측(CODEF) 단가는 비공개 → 견적 필수**.

**카드는 새 도메인 (SP-09-4 밖)**: 현 SP-09-4 = **입금(deposit) 매칭만**. 카드 = 신규 연동 + 신규 분개(비용/미지급금·카드대금) + **가맹점명→거래처/계정 매핑**. (`accounting-service` 의 `EcountCardImporter` 는 과거 eCount 마이그레이션용, 라이브 카드 연동 아님.)

**권고**: 카드 포함이면 **CODEF 통합 단일 채널을 1순위로 견적**(계좌+카드 한 번에, 자격/보안 회피). 계좌 물량이 매우 크고 장기면 계좌만 오픈뱅킹 분리(하이브리드)를 비교. 온디맨드 유지. **카드/CODEF 단가 견적 필수.**

## 6. 권고 / 다음 단계

1. **✅ 개발책임자 결정(2026-06-17): 하이브리드** — 계좌 입출금내역 = **오픈뱅킹(법인 거래내역조회)**, 카드 사용내역 = **CODEF**. **조회(read) 전용**. CODEF 단일 시작 대안 미채택(계좌측을 처음부터 공식·저렴·안정 오픈뱅킹으로). 어카운트인포 카드는 개인용이라 법인 제외, 카드사 직접은 발급사 수만큼 N연동이라 CODEF 로 통합. 스크래핑 리스크는 카드(CODEF)에만 한정, 계좌측은 공식·안정.
   - **선행(차단) 액션**: ① 오픈뱅킹 **이용기관 자격**(적합성 심사 + 금융보안원 보안점검, 수개월) ② **CODEF 법인 계약** — 병행 착수 ③ 양쪽 **단가 견적**.
   - 연동 2개 운영 부담 수용(계좌측 공식·저렴·안정 우선).
2. **운영점** = **온디맨드(조회 버튼) 우선**(§2.6, 최저비용 + SP-09-4 기구현 모델). 자동 갱신이 필요하면 영업시간 5~10분 폴링을 옵션으로. 진짜 실시간 push 가 업무상 필수면 펌뱅킹 입출금통보 별도 검토.
3. **견적 확보**(차단 항목): ① 호출단가(조회) ② 월 기본료/최소이용료 ③ 일/월 조회 한도 ④ 자격(적합성 심사 + 금융보안원 보안점검) 비용·기간 — 주거래은행/KFTC.
4. **구현** = Phase 11 에서 기존 SP-09-4 shell 위에 실 API + 원장 posting + 적요 매칭 고도화.

## 7. 미확정 (견적/추가조사 필요)

- 오픈뱅킹 이용기관 **실 운영 단가**(건당 외 월 최소료/기본료) + **일/월 조회 한도**가 다계좌 고빈도에 충분한지.
- KFTC 적합성 심사 + 금융보안원 보안점검의 **일반 사업자 통과 기준·소요기간·비용**.
- CODEF·뱅크다 **유료 운영 정가**(계좌당 vs 정액, 호출단가, SLA)와 자체구축 대비 **손익분기 계좌수**.
- 적요만으로 거래처 자동 매칭 **정확도** + 보조키(사업자번호·예금주명) 제공 채널.
- 오픈뱅킹 **~6개월 lookback** 제약 하 과거(이월·결산) 내역 보완(CODEF 12개월 등 하이브리드 필요 여부).
