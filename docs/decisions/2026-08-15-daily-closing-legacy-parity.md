## 레거시 원본 (저장소에 있다)

```text
tools/legacy-gas/일마감 프로그램/Code.js
tools/legacy-gas/일마감 프로그램/Index.html
```

GAS HTML 웹앱이다. 사용자가 Excel 을 업로드하면 첫 시트를 읽어 HTML 표로 렌더한다.

### 17열 명세표

```text
DC · 일자 · 번호 · 창고명 · 품목명 · 수량 · 단가(VAT포함) · 공급가액 · 부가세 ·
합계 · 거래처명 · 거래처코드 · 출고가 · 할인율 · 총계 · 확인 · 회계반영일자
```

### 구조

```text
전표(일자+번호)
  ├─ 품목 원본행 1
  ├─ 품목 원본행 2
  └─ 소계
전표(일자+번호)
  └─ 소계
전체 합계
```

- `DC·일자·번호·창고명·거래처명·거래처코드·회계반영일자` 는 전표 내 품목행에 걸쳐 **세로 병합**
- 탭 3개 — `결과`(회계반영일자가 날짜 아님) / `선발행`(날짜임) / `합산`
- 소계 대상: 수량·단가(VAT포함)·공급가액·부가세·합계·출고가·총계
- 전체 합계 대상: 수량·단가(VAT포함)·공급가액·부가세·합계 (나머지는 `-`)
- 숫자: `Math.round(Number(n)||0).toLocaleString()` — 정수·천단위·**0 과 빈값 모두 `0`**
- 할인율: 정수 `%` · 45~49% 배경색
- 확인: `TRUE`/`FALSE` 둘뿐

## 🚨 같은 이름, 다른 뜻

```text
DC         레거시  거래처 홈·상업 할인율 + 옵션 정액 DC + 단위처리 + 특이사항을 "/" 로 합친 설명 문자열
           현재    출고가 − 실단가 = DC액 (숫자)
거래처코드   레거시  실제 거래처 코드
           현재    사업자번호(bizNo) 숫자
```

⟹ **이름을 그대로 쓰면 두 값이 섞인다.** 어느 쪽 의미로 갈지 정해야 한다.

## 결정

### ① 범위 = **혼합형**

```text
✅ 상세 본문을 레거시 전표 구조로 바꾼다
   일자+번호 묶음 · 세로 병합 · 전표별 소계 · 전체 합계 · 창고명 · 회계반영일자
✅ 표는 하나로 통일한다 (개발책임자 추가 지시)
   레거시 3탭(결과 / 선발행 / 합산) → 표 하나
   🔑 사실상 레거시 "합산" 탭 하나만 남는 셈이다
   🚩 레거시가 결과/선발행을 나눈 기준은 "회계반영일자가 날짜 형식인가" 였다
      통일하면 그 구분이 화면 구조에서 사라지지만
      회계반영일자 컬럼 자체는 남으므로 값으로는 여전히 읽힌다
✅ 유지한다 (레거시에 없던 것이지만 버리지 않는다)
   마감 snapshot 목록 · 마감상태(열림/마감) · 마감범위 · 역마감
   확인 3상태 배지(확인/불일치/판정불가) + 사유
❌ 엄격 복귀 (레거시에 없던 것 전부 제거) — 기각
❌ 표기만 레거시로 — 기각
```

🔑 **`판정불가` 를 버리면 가격 미등록·모호·정가결측을 실제 불일치와 구별할 수 없다.** 레거시 `TRUE/FALSE` 로는 그 구분이 원천적으로 불가능하다.

### ② Excel 업로드 → **날짜 지정 조회**

```text
레거시  Excel 내보내기 → 업로드 → 첫 시트 파싱 → 17열 표
결정    날짜 하루 지정 → 출고전표에서 바로 조회 → 17열 표
```

🔑 **업로드는 출고전표 데이터를 밖으로 뺐다가 다시 넣는 왕복이었다.** 그 왕복을 없애면 파싱 실패·시트 형식 어긋남·오래된 파일 업로드 같은 사고 경로가 함께 사라진다.

```text
6  17열 중 출고전표에서 바로 안 나오는 것이 있는가
   🚩 회계반영일자 · DC 설명문자열이 후보다. 없으면 어디서 가져올지 정해야 한다
```

```text

2  🚨 마감 snapshot·역마감 업무가 후퇴하면 안 된다

   🔑 "같은 표를 그린다" 가 아니라 "같은 데이터를 본다" 가 먼저다
4  전표별 소계·전체 합계의 산식을 문서에 못 박아라
   레거시가 단순 합산하는 열까지 그대로 갈지가 결정 4다
5  🚫 이름이 같고 뜻이 다른 것(DC·거래처코드)을 그대로 쓰지 마라
```
