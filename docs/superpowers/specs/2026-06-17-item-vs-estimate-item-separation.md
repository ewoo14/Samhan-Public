# 에픽 — 기초품목 ↔ 견적품목 분리 (메뉴 2분화)

> 2026-06-17 개발책임자 결정. 에픽 #18(품목 노출/구성품 모델 재설계, #494/#495 완결) 후속 방향 전환.
> **메뉴명 확정**: **기초품목 관리**(물리 SKU 마스터) ↔ **견적품목 관리**(판매 카탈로그, 신규).

## 1. 동기 (왜 분리하나)

견적/주문 카탈로그는 **카테고리 컨텍스트를 본질적으로 품은 판매 도메인**임이 데이터로 확인됨:
- 같은 기능 판넬이 시스템(카테고리)별로 다른 SKU·단가 — 홈멀티 공청판넬 `PC4NUCK4NW` 611,050 vs 싱글 공청판넬 `PC6EUCK1NW` 556,600. (같은 SKU 가 카테고리별 다른 단가인 경우는 0건 — 단가는 SKU 단위로 결정적.)
- 거기에 번들 전개(싱글세트 실내:실외 6:4/4:6 재배분), 변동DC(useK2/$L$2), 옵션 SKU 선택(판넬/리모컨/자재) 로직까지 얹힘 (`BundleExpander`, GAS 종합견적서 1:1 이식).

이 판매-도메인 복잡도를 **물리 품목 마스터(재고·매입·회계)** 에 욱여넣으면(현 단일 products + usageScope + M:N 노출) 마찰 발생. → **두 관심사를 분리**.

## 2. 결정 (개발책임자 2026-06-17)

- **D-IES-01 분리**: 물리 SKU 마스터 ↔ 판매 카탈로그 분리. SKU 로 연결.
- **D-IES-02 메뉴명**: 마스터 = **"기초품목 관리"**(구 "품목 관리"). 판매 카탈로그 = **"견적품목 관리"**(신규).
- **D-IES-03 참조 제약**: 견적품목 관리에서는 **기초품목 관리에 등록된 품목만 추가**(미등록 신규 등록 불가, AsyncAutocomplete 선택). 기초품목이 단일 진실원.
- **D-IES-04 세트 구성 소관**: 세트(BUNDLE) **구성품 구성 정의(bundle_component, 무엇이 들어가나)도 견적품목 관리** 소관. (기초품목 관리는 세트 SKU 의 존재/종류만.)

## 3. 소관 분리

| 데이터 | **기초품목 관리** (물리 SKU 마스터) | **견적품목 관리** (판매 카탈로그) |
|---|---|---|
| SKU·모델명·규격·종류(단일/세트) | ✅ 등록·CRUD (source) | 참조만 |
| 납품가/출고가 (SKU별 1개) | ✅ | 참조 |
| 재고·매입·회계 연동 | ✅ | — |
| 견적/주문 노출 카테고리 (M:N) | — | ✅ (#494 슬1 자산 이관) |
| 카테고리별 표시순서 | — | ✅ (#494 슬1) |
| 세트 구성품 구성 (bundle_component) | — | ✅ (D-IES-04) |
| 구성품 표시순서·옵션 (판넬/리모컨/자재) | — | ✅ (#495 슬2) |
| 변동DC·번들 옵션 | — | ✅ |
| **추가 방식** | 신규 품목 직접 등록 | **기초품목에서 선택만** (D-IES-03) |

> 단가는 품목(SKU) 1개로 충분 — 판넬 per-카테고리 단가는 이미 SKU 분리(PC4 vs PC6 계열)라 견적품목에 per-카테고리 단가 override 불요.

## 4. 기존 자산 귀속 (버려지지 않음)

- **#494 슬1 (M:N 노출 + 카테고리별 표시순서)** → 견적품목 관리로 귀속.
- **#495 슬2 (세트 구성품 정렬 D-PCE-08 + display-orders 가드 D-PCE-09)** → 견적품목 관리로 귀속.
- 현 `ProductCatalogPage` → **기초품목 관리(등록 전용) + 견적품목 관리(노출/구성/옵션) 둘로 분화**.

## 5. 슬라이스 계획 (잠정)

- **슬1**: "견적품목 관리" 메뉴 + 화면 신설 — 목록 + **기초품목 선택 추가**(AsyncAutocomplete, 미등록 불가) + 노출(M:N)·카테고리별 표시순서 이관. 기초품목 관리에서 노출 UI 제거(등록 전용화).
- **슬2**: 견적품목 관리에 **세트 구성(bundle_component) + 구성품 정렬(#495) + 판넬/리모컨/자재 옵션** 이관. 기초품목 관리에서 구성품 모달 제거.
- **슬3**: 변동DC/번들 옵션 + **G1 카탈로그 DB 승격(견적품목 도메인 안에서)** — 변동DC Java FORMULA read 정확도 회복(상업멀티 useK2 378 parity) 포함.

## 6. 비-목표 / 재배치

- Java FORMULA read fix · G1 카탈로그 DB 승격 = **폐기 아님, 견적품목 도메인 슬3 으로 재배치**.
- estimate-app(종합견적서)는 견적품목 관리의 데이터 소비자 — 분리 후에도 카테고리별 카탈로그 구조 유지.
- 데이터 모델(products + product_estimate_exposure + bundle_component)은 대체로 유지, **메뉴/화면/참조제약 재구성**이 핵심(데이터 마이그레이션 최소).
