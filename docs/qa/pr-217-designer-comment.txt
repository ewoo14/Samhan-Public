### 검증 2 · design-system Input readOnly 적용 (line 178~203)

사이클 1 이전 `_codex_commit_repo` 원본 (line 178~203): **native `<input readOnly>` / `<textarea readOnly>`** 7건.

사이클 1.5 fix 후 PR #217 head (line 178~203): **`<Input readOnly inputSize="sm" value={...} />`** 7건 (거래처코드·연결전표·배송지·현장·연락처·납기·요청사항).

- `@samhan/design-system` `Input` 컴포넌트 forwardRef 확인: `readOnly` 는 `InputHTMLAttributes<HTMLInputElement>` 를 통해 `...rest` 로 native `<input>` 에 전달됨.
- `inputSize="sm"` → `size-sm` class: `height: 28px; padding: 0 var(--space-2); font-size: var(--font-size-sm)` — 폼 조회 전용 소형 인풋 적절.

**단, P1 신규 결함 — `Input.module.css` 에 `:read-only` 시각 스타일 없음.**
native `<input readonly>` 는 브라우저 기본으로 배경 회색 처리되나, design-system `Input.module.css` 에는 `.input:read-only { ... }` 선언이 없다. 결과적으로 readOnly Input 이 editable Input 과 시각적으로 구분되지 않음 — 조회 전용 필드임을 사용자가 인지 불가. 이카운트 reference 거래처등록 캡처에서 조회 전용 필드는 배경색 구분 또는 커서 변경으로 명확히 구분된다.

권고: `Input.module.css` 에 아래 추가 필요 (다음 사이클).
```css
.input:read-only {
  background-color: var(--color-bg-muted);
  cursor: default;
}
```

### 검증 4 · 신규 발견

사이클 1 이전 원본에서 `요청사항` 은 `<textarea readOnly>` 였으나, 사이클 1.5 fix 후 `<Input readOnly>` (단일 라인) 로 교체됨. 긴 메모 내용이 잘릴 수 있음. 이카운트 reference 거래처등록 캡처의 `적요` / `특이사항` 필드는 멀티라인 textarea 형태. design-system 에 `Textarea` 컴포넌트가 없다면 `<Input as="textarea">` 또는 native textarea 에 design-system 클래스 적용 방안 검토 권고.
