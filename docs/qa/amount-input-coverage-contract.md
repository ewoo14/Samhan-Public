# 금액 입력 커버리지 계약의 현재 한계

현재 React/TypeScript 코드 구조에는 새 금액 입력 화면의 누락을 자동으로 전수 탐지하는 신뢰 가능한 계약이 없다.

다음 방식은 모두 계약으로 사용하지 않는다.

- 특정 함수 사용처를 세는 방식: 다른 입력 구현을 놓친다.
- 소스 문자열/정규식 탐색: `type={'number'}`, 변수로 분리한 `type={inputType}`, 래핑 컴포넌트를 우회할 수 있다.
- 합성 인스턴스 또는 수동 화면 목록 렌더: 목록 밖의 실제 화면을 검증하지 않는다.

실측상 기존 정규식 계약은 아래 세 fixture가 추가된 상태에서도 다음 결과를 냈다.

```text
Test Files 1 passed (1)
Tests 2 passed (2)
```

따라서 해당 자동 계약은 제거했다. 현재 금액 표시/키보드/서버 값 보장은 각 실제 화면의 렌더 테스트와 공통 금액 입력 유틸리티 테스트로 유지한다. 새 화면 전수 누락을 자동으로 막으려면 금액 입력을 단일 강제 컴포넌트/타입 경계로 제한하거나, 컴파일·린트 단계에서 모든 입력 생성 경로를 차단하는 별도 아키텍처 계약이 필요하다.
