## 3. 발송금지

### 3.2 왜 비었는가

현재 CSV의 `생성 일시`는 ISO UTC 형식이다. `PartnerBlockImportService`는 `yyyy년 M월 d일 a h:mm`만 파싱하고, 시각 파싱 실패를 행 reject로 처리한다. 현재 파일을 그대로 import하면 여섯 행이 모두 `PARSE_ERROR`가 된다. 테스트 fixture도 한국어 시각만 사용해 실제 export 형식 차이를 잡지 못한다.

### 3.3 업무 영향

- 관리 화면 목록은 0건이므로 여섯 거래처가 발송금지로 보이지 않는다.
- notification preview와 send 직전 검사는 partner DB의 활성 차단 집합을 읽는다. 집합이 비어 있어 여섯 거래처를 차단하지 못한다.
- slip의 내일자 이미지 경로도 같은 집합을 읽으므로 일반 거래처처럼 포함될 수 있다.
- 레거시 내일자 이미지의 별도 코드 예외 `8428102605`도 현행 DB에는 없다.

## 7. 개발책임자 확인이 필요한 것

1. **정본 결정:** 2026-07-28 CSV/Notion과 현행 DB 중 무엇이 현재 업무 정본인가. 네 데이터 모두 자동 동기화되지 않는다.
2. **BLOCK:** 여섯 거래처와 별도 GAS 예외 `8428102605`가 지금도 발송금지인가. 금지가 preview 경고인지, 목록 제외인지, 실제 send hard block인지도 확정해야 한다.
3. **DC 92 누락:** 원천의 partner-specific 설정을 신규 적재할지. 91코드는 금액에 닿는다.
4. **DC 43 drift:** 표의 원천/현행 중 어느 값을 채택할지. 특히 audit이 있는 `4348703365`, 단위처리 3코드, 옵션 정액 차이를 일괄 덮어쓰면 안 된다.

## 8. 적재 초안 — 실행하지 않음

아래는 결정 후 PM이 migration을 작성할 때의 검증 구조다. 이번 정찰에서는 실행하거나 파일로 만들지 않았다.

### 8.1 BLOCK 초안

```sql
-- 실행 전 개발책임자가 6코드의 현재 유효성을 승인해야 한다.
-- 내부 PK 값은 애플리케이션의 표준 생성 전략을 사용한다.
WITH approved(partner_code, blocked_at) AS (
    VALUES
      ('3128640516', timestamptz '2026-04-25 22:36:20Z'),
      ('1428116616', timestamptz '2026-04-25 22:36:54Z'),
      ('6348602237', timestamptz '2026-04-25 22:36:57Z'),
      ('1068616876', timestamptz '2026-04-25 22:36:49Z'),
      ('1138620591', timestamptz '2026-04-25 22:36:40Z'),
      ('2188121662', timestamptz '2026-04-25 22:36:46Z')
)
INSERT INTO blocked_partners
    (id, partner_code, partner_business_name_snapshot, blocked_at, source,
     created_at, created_by, modified_at, modified_by, is_deleted)
SELECT gen_random_uuid(), p.partner_code, p.name, a.blocked_at AT TIME ZONE 'UTC',
       'LEGACY_RECONCILIATION', now(), 'migration', now(), 'migration', false
FROM approved a
JOIN partners p ON p.partner_code = a.partner_code AND p.is_deleted = false
WHERE NOT EXISTS (
    SELECT 1 FROM blocked_partners b
    WHERE b.partner_code = a.partner_code AND b.is_deleted = false
);
```

### 8.2 DC 초안

```sql
-- legacy_dc_stage는 승인된 CSV snapshot을 migration 내부 VALUES/COPY-equivalent로
-- 고정한 staging 관계라는 전제다. 현재 importer를 호출하면 0.45가 0.0045가 될 수 있다.
-- 2291465974 중복과 43 drift는 승인 테이블에서 코드별로 명시 결정한다.

SELECT partner_code, count(*)

HAVING count(*) <> 1;

SELECT partner_code

   OR commercial_discount_rate NOT BETWEEN 0 AND 1;

WHERE NOT EXISTS (
    SELECT 1 FROM dc_configs d
    WHERE d.partner_id = p.id AND d.is_deleted = false

UPDATE dc_configs d
```

```sql
-- CHAT: 두 신규 코드는 insert 후보. 6068199542는 승인 후에만 방명 update.
```
