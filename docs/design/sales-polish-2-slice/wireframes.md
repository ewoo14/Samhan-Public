### 1.5 구현 패턴 (FE 인용)

```typescript
// hooks/usePageTitle.ts
export function usePageTitle(title: string, meta?: string) {
  const setPageTitle = usePageTitleStore((s) => s.setPageTitle);
  useEffect(() => {
    setPageTitle({ title, meta });
    return () => setPageTitle({ title: '', meta: undefined });
  }, [title, meta, setPageTitle]);
}

// SlipDetailPage.tsx
function SlipDetailPage() {
  const { slip } = useSlipQuery(...);
  usePageTitle('출고전표 상세', slip?.slipNo);
  // ...
}

// AppLayout.tsx
function AppLayout() {
  const { title, meta } = usePageTitleStore();
  return (
    <header className="app-header">
      <h2>
        {title || '업무 화면'}
        {meta && <span className="meta">[{meta}]</span>}
      </h2>
      ...
    </header>
  );
}
```

### 2.5 노드 / 라벨 visual

| State        | 노드                                    | 라벨                                    |
| ------------ | --------------------------------------- | --------------------------------------- |
| done         | 32px ● 파란 배경 (`--action-brand`)     | 12px 일반 weight, primary text          |
| current      | 32px ● 흰 배경 + 2px 파란 외곽선        | 12px **600 weight**, brand color        |
| todo         | 32px ○ 흰 배경 + 2px 회색 외곽선        | 12px 일반 weight, tertiary text         |
| rejected     | 32px ⊗ 빨간 배경 (`--state-danger`)     | 12px 600 weight, danger color           |
| canceled     | 32px ⊗ 회색 배경 (`--ink-tertiary`)     | 12px 600 weight, tertiary color         |

### 2.6 연결선 spec

```
done → done       : 2px solid var(--progress-line-color-done)    (파란색)
done → current    : 2px solid var(--progress-line-color-done)    (파란색)
current → todo    : 2px solid var(--progress-line-color-todo)    (회색)
todo → todo       : 2px solid var(--progress-line-color-todo)    (회색)
last-done → rejected: 2px solid var(--progress-fill-rejected)    (빨간색)
last-done → canceled: 2px solid var(--progress-fill-canceled)    (회색)
```

분기 (REJECTED/CANCELED) 후 노드는 모두 `todo` state 로 회색 표시 + 라벨 옅음.

### 3.4 규격 input 동작

- 사용자가 직접 입력 (자동 fetch X — 모델명마다 표준 규격 정의 안 됨)
- placeholder: `예: 220V` (없으면 한 글자 — 시스템에어컨 의미 없는 placeholder 회피)
- maxLength 50 (DB column varchar(50))
- 빈 값 허용 (모든 라인 규격 입력 의무 X)
- 출력 시 빈 값은 `-` 표시 (DispatchView 라인 표)

| (없음)    | -          | -      | **마지막 빈 열 삭제**                |

전체: 8 + 8 + flex + flex + 18 + 14 = 48mm + flex (총 186mm 본문 폭)

### 4.4 배송지 / 연락처 / 특이사항 14pt (피드백 #6)

#### 4.4.1 기존 (1차 — 11pt)

```css
.dispatch-section .label   { font-size: 9pt;  }
.dispatch-section .content { font-size: 11pt; }  /* 본문 작음 */
```

#### 4.4.2 신규 (Slice A — 14pt 본문)

```css
.dispatch-section .label   { font-size: 12pt; font-weight: 700; }  /* var(--print-text-md) */
.dispatch-section .content { font-size: 14pt; }                    /* var(--print-text-base) */
```

라벨도 9pt → 12pt 확대 (가독성 우선).

### 4.5 용달기사/인수자 서명 잘리지 않도록 (피드백 #8)

#### 4.5.1 기존 (1차 — 60mm × 40mm)

```
┌──────────────┐    ┌──────────────┐
│ 용달기사 서명 │    │ 인수자 서명   │
│              │    │              │
│  60mm × 40mm │    │  60mm × 40mm │
│              │    │              │
└──────────────┘    └──────────────┘
gap 8mm — 총 폭 128mm — 페이지 하단 page-break-inside: avoid
```

배송지/연락처/특이사항 영역이 길어지면 서명 박스가 page bottom 으로 밀려 잘림 발생.

#### 4.5.2 신규 (Slice A — 80mm × 35mm + budget 재계산)

```
┌────────────────┐    ┌────────────────┐
│ 용달기사 서명   │    │ 인수자 서명     │
│                │    │                │
│  80mm × 35mm   │    │  80mm × 35mm   │
│                │    │                │
│ (서명 대기 —   │    │ (서명 대기 —   │
│  Slice C)      │    │  Slice C)      │
└────────────────┘    └────────────────┘
gap 6mm — 총 폭 166mm
```

- 박스 높이 40mm → 35mm (1차 대비 5mm 감소)
- 박스 폭 60mm → 80mm (서명 길어도 잘림 방지)
- gap 8mm → 6mm
- A4 portrait 273mm 본문 안에 모든 섹션 들어가도록 budget 재계산 (`tokens.md` §1.3 `--print-budget-*`)

### 4.6 인쇄 색상 정책 (1차 계승)

- 모든 border `#000`
- 텍스트 `#000`
- thead 배경 `#F0F0F0`
- 결재란 라벨 영역 배경 `#F0F0F0`
- 컬러 절제 (사진/로고만 컬러 가능)
